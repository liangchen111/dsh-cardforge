# 制卡工具（forge）

给 [ElecKoi](https://github.com/eleckoi/ElecKoi)（PC + Android）做的一套**制卡工具**：  
从零开一张卡、改一张已有卡、校验、挂模块、换皮肤、组装卡内界面、打包、和酒馆（SillyTavern）来回搬、出文档。

核心三条约定：

- **`spec.yaml` 是唯一真相，`card.json` 是派生物。只手改 spec。**
- **一个卡工程分两层**：内容住 `source/`，界面住 `hud/`。改哪层动哪层，互不打扰。
- **颜色和版式分两份文件**：颜色住 `hud/主题.css`（由 `forge theme` 写），版式住 `hud/hud.css`。  
  换皮肤不会碰到机制，改机制也不会把配色弄丢。

## 装法（三种，按需挑）

这是个**文件夹工具**：`forge.py`、`forge/`、`assets/`、`samples/`、`向导/` 要待在一起。

```
# ① 不装，直接跑（最省事）
python forge.py <命令>

# ② 不装，当模块跑（等同 ①，给不想记文件名的人）
python -m forge <命令>

# ③ 装成 `forge` 命令（推荐）
pip install -e .        # 必须带 -e
forge <命令>
```

依赖只有一条：`PyYAML`（`pip install PyYAML`），其余全用 Python 标准库（≥3.9）。

## 给别人怎么用（三种交法，别搞混）

**预设和角色卡没有「贴个网址就装上」的路。** 这两种**只认本机文件**（源码口径：预设的安装来源只有「内建」和「用户导入」两种，没有网络装载通道）。**插件不一样 —— 「添加插件」接受包名、Git 地址、压缩包和本地绝对路径四种写法。** 所以这个仓库**本身就是一只能贴链接安装的插件**（根目录的 `package.json` ＋ `cordis.patch.yml`），见下表第 4 行。

| 对方想要什么 | 给他什么 | 他怎么用 |
|---|---|---|
| 只是想在做卡时被 AI 陪着 | `向导/制卡助手/成品/制卡助手.preset.png` | ElecKoi →「预设管理器」→「导入预设」→ **分类必须选「创作预设」**（选错会提示「这不是创作预设。」）→ 选中该预设 |
| 想在对话里直接问「怎么建卡」 | `向导/制卡助手/成品/制卡助手.card.png` | 当普通角色卡导入（手机端「导入角色」也认这张） |
| 自己要做卡 | 仓库链接或出厂 zip | 解压后 `python forge.py plan` 开工；也可以 `pip install -e .` 装成 `forge` 命令 |
| 想常驻 ElecKoi 界面 | 这一行就是仓库地址 | ElecKoi 侧栏「插件」→「添加插件」→ 贴 **`https://github.com/liangchen111/eleckoi-cardforge`** → 安装 → ★ **装完重启一次 ElecKoi**（插件在宿主启动时载入，不重启不生效）（想装本机改动版就贴 `插件/制卡工坊/` 的目录路径） |

**装插件这一条顺带把预设也装好了。** 插件加载时会检查 ElecKoi 里有没有「制卡助手」这个创作预设：没有就**自动导入**仓库里那份，有就一个字不写；紧接着，**如果当前的创作预设还是官方默认那个**，就把它切成「制卡助手」——你自己挑过的创作预设一律不动。所以第 1 行那步手动导入，走第 4 行这条路的人可以省掉。**前提是重启过一次**：插件只在宿主启动时载入，装完直接看预设列表是空的，`Alt+F4` 重进就有了（2026-10-15 实测）。

两条关掉的开关（在插件配置里，默认都开）：`installPreset: false` 完全不碰预设，`activatePreset: false` 只导入、不切当前。

**「找不到 Python」不用配。** 插件配置里的 `python` 留空就是**自动找**：先看你有没有设 `FORGE_PYTHON`，再挨个试常见位置（用户目录装的 Python、`C:\Python3xx`、DSH 自带那份、`PATH` 上的 `python3` / `python` / `py -3`），**真跑一次 `import yaml`**，谁能跑通用谁——因为 forge 要 PyYAML，而 Windows 上「装了 Python」不等于「`python` 在 PATH 上」。实在找不到，工具会告诉你它找过哪些地方，装一个 Python（勾「Add to PATH」）重启 ElecKoi 即可；机器上有好几个 Python 挑错了，才需要在 `python` 那一行写死完整路径。

**卸载插件不会带走那个预设 —— 这是故意的。** 预设存在 ElecKoi 自己的数据里，插件一卸它就没人管了；不自动删是因为你可能已经改过它，删掉就是数据丢失。不想要就在「预设管理器 → 创作预设」里把「制卡助手」删掉。

**点安装报「连接 GitHub 超时」＝这台机器到 github.com 不通。** 插件管理器的预检只有 5 秒（`git ls-remote`），直连时实测 21 秒都连不上。两条路：① 给 git 配代理 —— `git config --global http.https://github.com/.proxy http://127.0.0.1:你的代理端口`（配完裸 `git ls-remote https://github.com/liangchen111/eleckoi-cardforge.git` 应在 5 秒内出结果；不想要了 `git config --global --unset http.https://github.com/.proxy`）；② 点「试试其他方式」，改成贴**本机插件目录的绝对路径**（就是出厂包里 `插件\制卡工坊` 那个目录，形如 `X:\你的工具目录\插件\制卡工坊`），完全不碰网络。

**卡做在哪个目录，也不用每次说。** 插件配置里的 `cwd` 留空就是**`<你的用户目录>\Documents\ElecKoi卡库`**（没有就自动建）；调用时给了 `cwd` 参数就听参数的（参数 > 配置 > 默认）。想换地方就把 `cwd` 写成你要的目录，或每次调用带上。

PNG 那两个成品是**可直接分发的单文件**，对方不需要装 Python、不需要克隆仓库。要改内容再重新导出：

```
python forge.py coach                      # 重新生成规程 + 向导卡源
python forge.py preset 向导/制卡助手/source/制卡助手.spec.yaml --png
python forge.py png    向导/制卡助手/source/制卡助手.spec.yaml
```

> **为什么必须 `-e`（可编辑安装）**：这个仓库里 CLI 的**实体**是根目录的 `forge.py`，
> 而 `forge/` 是它的内核包 —— **两个同名**。普通 `pip install .` 只会装走 `forge/` 包、
> 装不走 `forge.py`，`forge` 命令就找不到它。可编辑安装把整个文件夹留在原地，
> 命令和资源（`assets/`、`samples/`、`向导/`）都还在。
>
> 顺带一句：因为同名，`import forge` 拿到的是**内核包**，不是 CLI；所以 `forge/cli.py`
> 只做一件事 —— 找到仓库根，把 `forge.py` 当脚本跑起来。

## 三分钟上手

```
python forge.py plan                                   # ① 开工先落一份规划书（九节空模板 —— 填满再动手）
python forge.py new   我的世界                        # 开一张新卡（内容层 + 界面层一起生成）
python forge.py check 我的世界                         # 体检（含界面规矩、皮肤可读性）
python forge.py hud   我的世界 --写回                   # 改过 hud/ 之后重新组装界面
python forge.py build 我的世界/source/我的世界.spec.yaml 我的世界/成品/我的世界.card.json

python forge.py new   我的世界 --模块 骰子,备份        # 顺手接两块现成机制（条目+界面一起接）
python forge.py drop  备份 我的世界/source/我的世界.spec.yaml   # 后悔了就撤，接之前的样子还在账本里
python forge.py theme 墨夜 我的世界                     # 换皮肤（换完记得再 hud 一次）
python forge.py theme --巡览 我的世界                   # 五套皮肤摆一起对比
python forge.py bundle 我的世界                        # 打成一个工程包（分发 / 备份）
python forge.py import 我的世界.工程包.zip --到 同事的卡   # 收包：落到本地，成一张能接着改的工程
python forge.py new    深夜便利店 --从 同事的卡.card.json   # 接手现成的卡：界面层照抄骨架，内容层用它的
python forge.py theme  --导出 我的世界                   # 把这张卡调好的配色导成一份皮肤文件（可发人）
python forge.py png    我的世界/成品/我的世界.card.json  # 出卡图（.card.png，ElecKoi 手机端「导入角色」认的就是它）
python forge.py preset 我的世界/成品/我的世界.card.json --png  # 出「创作预设」（.preset.json / .preset.png）
python forge.py lint   我的世界/成品/我的世界.card.json  # 正文体检（防八股）：只查句式骨架，不查词
python forge.py lint   -                               # 刚写完一轮？直接从标准输入丢进去查（硬判据按「一轮」标定）
```

往卡里**加东西**（以前只能改已有的，现在能从无到有）：

```
python forge.py entry 我的世界 --新 "夜里的酒馆" --模板 关键词 --关键词 酒馆,打听
python forge.py entry 我的世界 --列                     # 看看条目长什么样
python forge.py entry 我的世界 --看 "核心 · 世界总纲"     # 读一条的全貌：正文全文 / 关键词 / 提示 / 触发…
python forge.py entry 我的世界 --改 "核心 · 世界总纲" --正文@世界总纲.txt   # 长正文写成文件再 @ 引，绕开命令行转义
python forge.py group 我的世界 --新 支线                # 分个组
python forge.py var   我的世界 --新 玩家.声望 --类型 number --初值 0   # 变量三处一次写齐
python forge.py regex 我的世界 --新 "清理变量" --模式 '…' --替换 '…'   # 加正则（Git Bash 里先 export MSYS_NO_PATHCONV=1）
python forge.py opener 我的世界 --正文@开场白.txt       # 换开场白（末尾那三个零宽标记工具负责，不用手改 JSON）
python forge.py opener 别人给的卡 --正文@开场白.txt      # 只有内容层的工程也认（收进来的单卡，spec 里那条就是真源）
python forge.py trash 我的世界                          # 删错了？都在这儿，--还原 1 放回最近一条
```

看全部命令：`python forge.py`

**在「不许删、不许改名」的环境里跑**（比如 ElecKoi 里的 AI 直接跑命令）：
任何命令后面加 `--沙箱`，或先 `export FORGE_SANDBOX=1`。forge 会切成「只创建、只覆盖」——
落盘直接覆盖目标、回收站改用墓碑、撤皮肤写空壳。代价是丢掉原子落盘，**能不用就不用**。

> 建议用一个装好 PyYAML 的独立 Python 环境（`venv` / `conda` 都行），别拿系统 Python 直接跑。

**不想碰命令行**：让 AI 来做。见下面「制卡向导」一节 —— 把需求说清楚，  
AI 照着规程把命令替你敲完，你只管验收。

## 制卡向导（`coach`）—— 教 AI 怎么做卡

上面那些命令是**给你**用的。如果你想让 AI 替你开新卡，缺的不是命令，是**一份 AI 读得懂的制卡规程**：

```
python forge.py coach            # 默认出到 ./向导/
python forge.py coach --到 D:\出到这儿
```

一份内容，两个出口：

| 产出                          | 给谁                                                         | 怎么用                                                                                                       |
| --------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `向导/AI制卡规程.md`              | **电脑上的 AI**（Claude Code / Codex / Cursor 这类能读写文件、能跑命令的） | 丢进对话，说「照这个给我做一张卡」，它就会问清需求、建工程、写条目、体检、出成品                                                                  |
| `向导/SKILL.md`               | 同上，但带 frontmatter                                          | 拷进你 AI 客户端的技能目录就能当技能用（如 `~/.claude/skills/eleckoi-card-maker/`；指针版、指向 `向导/AI制卡规程.md`）：新会话里直接说「做张卡」就会被唤起；规程更新后不用重装 |
| `向导/制卡助手/成品/制卡助手.card.json` | **ElecKoi 里的 AI**（陪你聊天那个）                                  | 直接导入 ElecKoi 挂上：它变成制卡师，在对话里一层层访谈你，每层交一段可直接用的条目内容                                                          |

两份出口共用同一套**方法论九篇**（机制 / 条目触发 / 预算 / 世界 / 故事 / 角色 / 写法 / 变量 / 界面），  
加一章**红线**（会被 ElecKoi 静默吃掉的写法：`变量条件` 会被降级、`single_condition` 平台不认、  
`agent_read_condition` 平台根本不读、变量三处同步少一处静默丢值……）。

**不想一次读完整份规程**（一万七千字，塞进上下文既贵又冲淡重点）：`forge.py guide` 先出目录，
再按需取一段 ——

```
python forge.py guide                 # 目录：有哪些节、有哪些篇、哪几篇必读、有哪几段「对话」
python forge.py guide --节 三          # 一节：三 开场白（一 开工流程 / 六 验收标准 / 九 红线 …）
python forge.py guide --篇 预算        # 一篇方法论（预算 / 写法 / 角色 / 世界 / 变量 …）
python forge.py guide --对话 访谈      # 一段「在对话里做卡」（总则 / 访谈 / 交付 / 红线）
python forge.py guide --全文          # 整份（等同 AI制卡规程.md）
```

写的名字认不出会**当场报错并列出全部候选**，撞名的（两篇同前缀）报「不止一个」让你写全 ——
绝不静默挑一个。装了「制卡工坊」插件的 AI 在 ElecKoi 里就是靠这条**自己把知识取到手**，
不必等人把规程贴进对话（自检第 43 项盯着「目录里说的每一段都真取得到」）。

向导卡**自己就是范例**：它由 `coach` 从骨架抄形状、用 `content.py` 写内容生成，  
所以它自己也体检 0 错、常驻字数守在预算内（自检第 28 项每次都盯着这两条）。

## 一次落成（`make`）—— 想清楚了就别来回跑

`new` → `group` → `entry` × N → `var` → `regex` → `opener` → `build` → `check` 是七八次进程启动。  
人用不累，**AI 在对话里用就贵**：每次调用都是一整轮（上下文从头重发一遍）。内容想清楚之后，  
真正要的是**一次落成**：

```bash
python forge.py make --示例        # 先打出一张**真能开的完整卡稿**（长夜便利店）—— 照着改
python forge.py make --模板        # 或者只要骨架：有哪些键、怎么缩进
python forge.py make 我的卡.yaml   # 一趟：建工程+写条目+加变量正则+换开场白+出成品+体检
```

`--模板` 只回答「有哪些键」，`--示例` 连「**话该写多细、哪句放常驻、哪句放关键词**」一起示范 ——  
AI 最容易失手的不是键名，是「写多细算够」，一份好样板比十条规则管用（同一份也落在 `向导/示例卡稿.yaml`）。

稿子写的是**这张卡该长什么样**，不是「先做这步再做那步」：

- **条目按标题认人** —— 卡里已有同名的就改它，没有才新建。不必先搞清楚骨架里现成有什么。
  想清掉骨架自带、而稿子里没提到的条目，写一行 `清空条目: true`；想删掉某一条，写 `删: true`。
- **给已有条目写 `模板:` / `分组:` 也真生效**：换档（常驻 ↔ 必读 / 关键词 / 选读）与挪组都会落下去。
- **分组 / 变量对象缺了自动补**，只在报告里单列一份（名字打错才看得见）。
- **全程在临时目录里做，全绿了才整棵拷到目标位置。**
  稿子有毛病时**目标位置一个字都不会被写** —— 这是这个命令最要紧的一条；
  静态能查的（模板名 / 类型 / 值域会不会被静默降级）**一次报全**，不用改一处跑一次。
- `--试` 只验证不出；`--覆盖` 才允许把已有的同名卡工程照稿子重落（别的东西一律不碰）。

它也是**沙箱友好的**（全程只创建、只覆盖）—— 在 ElecKoi 里直接跑命令的 AI 加 `--沙箱` 照样一趟落成。  
（自检第 44 项盯着上面这几条：坏稿一个字不写、目标已有不给 `--覆盖` 就停、别人的目录给了也不给盖；  
第 45 项盯着这份示例自己就是绿卡、以及「给已有条目换档 / 挪组」真的落下去。）

**规程是「走过一遍」的，不是「想出来」的。** 一份规程写完就丢给 AI，多半会烂在细节里 ——  
所以它被拿去做过**五轮盲跑**：一个不看内部代码的 AI，只拿这份规程照章施工，把每一处卡壳如实记下来。  
第一轮施工「从零建一张卡」，修回 15 处；第二轮施工「**接手一张别人给的卡**」，又挖出 10 处 ——  
最要命的一处是条死路：单张卡收进来没有界面层，`opener` 不认、`hud` 不肯凭空造、规程又让人别手改，  
于是「改开场白」整条链路闭合不了，最后只能手抠那三个零宽标记（正是这个工具最该消灭的错）。  
现在 `opener` 多认一档**内容档**，死路通了；`entry --改` 也不许再碰开场白正文。  
第三轮的目标就是那处死路的根治：规程原来只剩一句「开新卡把条目搬过去」，而**根本没有搬运命令** ——  
现在有了（`new <卡名> --从 <卡>`：界面层照抄骨架、内容层用卡里的）。  
自检第 29 项盯着「规程里的命令 / 模板名 / 类型名必须真实存在」且**不许留有老写法**，  
第 32 项盯着「接手别人的卡」与「不许静默丢改动」，第 33 项盯着「搬运」这条新路，  
第 34 / 35 项盯着「每条命令的 `--help` 要给得出自己的用法」与「卡名两处不许飘」，  
第 36 / 37 / 38 项盯着「变量改名三处一起挪、撤销逐字还原」「条目批量一次落盘、认不出的名字整批停下」  
与「变量换对象：挂靠 / 初值那格 / Zod 那个字段 / 排序一起搬，id 不动」，  
（编号 21 / 39 / 40 原为图形工作台，v0.27.0 已随工作台迁出 → `弃用/工作台/`。）  
第 41 项盯着「条目复制」：一次能复制一串（副本**顺在各自原件后面**、默认「原名（副本）」、  
内容原样、id 全新）、`--到 分组` 能让副本直接落进那个组、认不出的名字整批停下、开场白条目不许复制。  
第 42 项盯着「**不许删、不许改名时也能干活**」：把三个删改函数换成炸弹再跑一遍开卡全流程，
一个都不许碰到 —— 这条给「在 ElecKoi 的沙箱里直接跑 forge.py」那条路站岗。

### 为什么插件比「让 AI 用自带命令行工具」强

ElecKoi 自己的命令行工具跑在**受限令牌沙箱**里（读得到、写得进，但**不许删、不许改名**，
`WinError 5`）。而 forge 每次落盘都靠改名（`os.replace` / `os.rename` / 回收站是「移动」）。
**宿主插件起的子进程不受那层沙箱管** —— 于是原子落盘、改名、回收站全都回来了。

一句话分工：**能用插件就用插件（全功能）；只能用命令行工具就加 `--沙箱`（丢掉原子落盘，但能干活）。**

### 另一条路的实测结论：能不能让 ElecKoi 里的 AI 直接跑 `forge.py`？

ElecKoi 的 AI 手上本来就有命令行工具和文件工具，每个会话默认「工作区可写」——
若它直接能跑 `forge.py`，连插件都省了。**本机实测（把沙箱代码从 `app.asar` 抽出真跑 11 组对照）**：

- 沙箱机制**是通的**：受限令牌下系统自带的 PowerShell 5.1、`cmd`、`node` 退出码全 0；全链路也通。
- `forge.py` **能启动、能读工程、能往工作区写**。
- **但「删除 / 改名」被沙箱拒了**（`WinError 5`），而 `forge.py` 每次落盘都靠改名（`os.replace`）
  ⇒ 那条路原本卡在最后一步。

**已经修掉了**：任何命令后面加 `--沙箱`（或设 `FORGE_SANDBOX=1`），forge 就切成
「**只创建、只覆盖**」—— 落盘直接覆盖目标（不改名）、临时文件删不掉不算失败、
回收站改用**墓碑**、撤皮肤改成写**空壳**、撤模块留着目录（组装只看 conf）。
代价是丢掉原子落盘，所以能用普通模式就用普通模式。自检第 42 项盯着这条：
把三个删改函数换成炸弹，开卡全流程一个都不许碰到。

上面这套测法、结果表与矛盾点结论留在开发笔记里，**不随包发布**；结论本身已经写进 `--沙箱` 的实现与自检第 42 项。

## 护城河是什么

**一、真值域表。** ElecKoi 对不认识的字段值**静默降级**，不报错。比如  
`agent_read_strategy: variable_condition` 会被悄悄改成 `normal`——症状是「填了没反应」。  
市面上的酒馆制卡工具都不知道这件事。本工具把反编译取证出来的真值域表变成了会拦截的代码。  
看全表：`python forge.py domains`

顺带一提：**骨架自己原来也踩着这几颗雷**（`single_condition` / `agent_read_condition` /  
`variable_condition`），本工具把它清干净了，所以新卡一出生就是绿的。

**二、变量三处同步。** 变量要同时写在三处（`objects` 画面板 / `initial_state` 供初始化 /  
`schema_code` 过 Zod）。少任何一处都不会报错，只会安静地少一块——`schema_code` 那一处尤其阴，  
写入**被静默丢掉**。`check` 会把这三处对一遍；加变量时工具一次替你写全三处，  
`var --对齐` 能把已经歪掉的补回来。

**二·补、形状不猜。** `initial_state` 里那个「对象」到底是一层对象还是平的一格，**是卡自己写的**。  
工具读卡判断：对得上就写，对不上就当场告诉你**是哪一格挡着**，绝不猜着往里塞  
（猜错的后果是值被塞到旁边那一层，而且不报错）。删的时候反而从宽——只认「在不在」，删错有回收站兜。


**三、界面层的边界守则。** HUD 是整段注进宿主页面的，越界一处宿主界面就跟着变形。  
`check` 会逐文件扫：三反引号 / `<!--` / `</script` 字面量 / 模块里的 `position:fixed`，  
以及 **CSS 每个选择器必须带 `.hud` 前缀**（漏一个裸选择器就把宿主染了）。

**四、模块可撤。** 模块是**覆盖**进 spec 的，不存原样就再也回不去。所以每接一个，  
都把「替换的那条原来长什么样」整份存进 `模块账本.json`；`forge drop` 于是能精确撤回：  
替换的还原、新增的删掉、正则按 id 删、界面文件与登记一并摘掉。  
**你自己手写进 spec 的东西，工具一个字都不动**——它分不清那是谁的，宁可不撤。

**五、换皮肤不碰机制。** 全部颜色都在一组 `--hud-*` 槽里，`hud.css` 里一个色值都不硬编码。  
主题只写这组槽，所以：换皮肤不可能弄坏版式、核心升级不会覆盖你的配色、同一份主题跨卡通用。  
外带**对比度体检**——卡的底是半透明的，压在宿主背景上到底看不看得清，  
按「宿主纯白 / 宿主近黑」两路各算一遍取更差的那个（浅灰字配浅底的坑，预览时看不见）。

**六、双向无损。** `to-tavern` 把变量、分组、未映射字段、条目 id 与顺序全部存进  
`data.extensions.eleckoi`；`to-eleckoi` 认得出它，走「回迁」路径取回来。  
已验：艾瑟兰 2.5MB 实卡 ElecKoi → 酒馆 → ElecKoi，**语义完全一致**。

**七、能力缺口的诚实交代。** ElecKoi 有「由 AI 自己选读」这一档（`agent_tool` + `normal`），  
酒馆没有对应能力。转过去时这些条目会变成「永不自动触发」，工具会**点数并说清根因**，  
而不是假装转换成功。同理，模块的脚本/样式在宿主接口不通时会被如实标注，不静默降级。

**八、值域在写入那一刻就拦下。** 凡是值域字段（触发方式 / 读取策略 / 内容模式…），  
`set_entry` 一律先对真值域表，会静默降级的当场拒收、并写明「会被降级成什么」——  
让人没有机会「填了不生效」。这是把护城河从「事后检查」提到「事前就不可能填错」。

**九、工程层也要对得上。** 前八条管的是「这张卡自己通不通」；还有一类错在**工程**里，  
而且它们**一个都不报错**：模块目录在、`hud.conf.json` 没登记它（组装只按 conf 拼 →  
界面上安静地少一块）；接过模块、`模块账本.json` 没记（`forge drop` 撤不掉，你以为撤了）；  
改了 spec、没重出成品（**交付给 ElecKoi 的是成品** → 导进去的还是老内容）；  
`hud/` 在、HUD 那条正则没写回 spec（界面根本不会出现）。  
`check` 现在会照着 `PROJ-*` 逐条查，`forge hud` 组装时也会主动报一句  
「这个目录没登记，不会被拼进去」—— 把「安静地少一块」变成当场说一句。

第二十四项验 Zod 保形（真实 `schema_code` 拆了再拼，**逐字相同**，且改一个叶子只动那一个）；  
第二十五项验内容增删（建条目 / 建变量 / 建正则 → 打包 → 校验全绿 → 删掉 → 从回收站还原，往返一致）；  
第二十六项验**变量三处同步**（新变量必须同时落进面板对象、初值、Zod 校验码三处）；  
第二十七项验**工程自洽**（模块目录↔conf、账本↔现状、界面没写回、成品过期、两份 spec  
—— 七种「不报错的错」都要查得出，同时**模板源那种本来就没成品的工程一条都不许报**）；  
第二十八项验**制卡向导**（出规程 + 出向导卡：规程成篇、技能有 frontmatter、卡体检 0 错、  
解包往返一致，并且**向导卡自己守着「常驻不超预算」这条规矩** —— 教别人省，自己不能胖）；  
第二十九项验**规程与工具对得上**（规程会腐烂：工具加了命令、改了值域，规程还写着老样子 ——  
它里面每一条命令 / 模板名 / 类型名都得真实存在，九节都得齐；反面还查一条 ——  
**规程里不许再残留「手改 conf 改开场白」的老写法**。规程最容易烂成自相矛盾：  
§三 已经改成「用 `opener`」，§八 的示例里还抄着老写法，而 AI 抄的正是 §八。  
第三十项验**制卡读写回路**（AI 改一张卡的两个最短动作：先 `entry --看` 读一条现在写了什么 —  
正文原样、多行不糊、读它不落盘；再用 `--正文@文件` 把长正文写回去 ——  
两种写法都认、换行引号反斜杠原样、路径写错当场拦下）。  
第三十一项验**开场白**（真源在 `hud.conf.json`、spec 里那条是派生物 —— 改一处必须两处齐；  
末尾那三个零宽标记永远正好 3 个、且写成转义 `\u200b` 跟模板一个风格；  
尖括号与空正文一个字都不落盘；标记被弄丢能读出来、写回被拒、`--补齐` 修好；旧版进回收站）。  
第三十二项验**接手别人的卡 + 不许静默丢改动**（单卡收进来就能改开场白 —— 内容档、  
标记自动齐、方案正文同步；`entry --改` 不许碰开场白正文；文件被抢改过就拒写且一字不动；  
正常一读一写不误拦）。  
第三十三项验**搬运**（`new <卡名> --从`：单张卡与酒馆卡都能连界面层一起建，开场白取自来源  
而不是骨架那句，conf 与 spec 两处齐、标记正好 3 个；**非 ElecKoi 卡不许被「解包成功」成空工程**；  
接手失败不留半成品目录；开场白条目正文空着 / 与各方案对不上都查得出）。  
第三十四项验**子命令用法**（每条命令 `--help` 都要给出**它自己**的用法，而且一条都不许写盘 ——  
以前 `entry --help` 回的是总表，唯一线索是总表末行那句「去掉参数直接跑」，没人会去猜）。  
第三十五项验**卡名与接管**（`--从` 之后名字归新卡、不许顶着来源卡那个旧名；`name --改` 两处一起动；  
来源里「已禁用」的条目列得出、也改得动；回收站还原连界面配置一起回去）。  
第三十六项验**变量改名**（一次把三处一起挪：面板 / 初值那一格的键 / Zod 里那个字段名；  
id 不动、**别的字节一个没改**（改名前后整段 schema 只有名字变）；对象改名同办；  
同一层里重名拦下；撤销能把三处逐字还原回原样）。  
第三十七项验**条目批量**（挪组 / 启停 / 删都一次落盘、一条回收记录；**有认不出的名字就整批停下、  
一条不动**；删掉再还原，顺序 / 分组 / 启用状态全齐）。  
第三十八项验**变量换对象**（名字不动，挂靠 / 初值那格 / Zod 那个字段 / 排序一起搬到新对象那棵子树下；  
变量 id 不动；换到同一对象、对象不存在当场拦且**不落盘**；新层里重名拦下；撤销把这四处逐字还原）。  
第四十一项验**条目复制**（一次复制一串：副本顺在各自原件后面、默认「原名（副本）」、内容原样、  
id 全新；`--到 分组` 能让副本直接落进那个组、不给就跟着原件；认不出的名字整批停下；  
开场白条目不许复制 —— 一张卡只有一条开场白）。  
第四十二项验**沙箱友好模式**（把 `os.replace` / `os.remove` / `rmtree` 三个全换成炸弹，  
模拟「能读能写、但不许删、不许改名」的文件系统 —— 再把「开新卡 → 加条目 → 出成品 → 验卡」  
整条走一遍，**全程一次都不许碰到那三个**；碰到就说明还有地方依赖删/改名，  
那条「在 ElecKoi 的沙箱里直接跑 forge.py」的路就会在那一步挂掉）。  
第四十三项验**规程取节**（`guide` 目录里列出的**每一节 / 每一篇 / 每一对话段**都要能真取到、  
且取出来不是空壳 —— 目录说有的、取不到，AI 只会以为规程就这么多，然后照着半份知识做卡；  
负向两侧：认不出的名字当场非 0 并列出全部候选、撞名的报「不止一个」而不是挑一个）。  
第四十四项验**卡稿落卡**（一份稿子一次落成一张卡：改 / 建 / 删 三种条目处理都对）
—— 负向三条：稿子写坏时**目标位置一个字都不许写**、目标已有一份工程（没给 `--覆盖`）要停、
别人家的目录（给了 `--覆盖` 也不许盖）；顺带把「`make --模板` 给的那份骨架自己跑得通」钉住。  
第四十五项验**示例卡稿**（`make --示例` 打出来那份 3.8k 字的完整卡稿**自己就是绿卡** ——
样板自己跑不通比没有样板更坏；再把「给**已有**条目写 `模板:` / `分组:` 真生效」钉住，
这两条以前一条会当场抛 `kind 不给改`、另一条**默默忽略**、一个字都不报；
负向：变量跟骨架重名要给一句人话，不许抛 traceback）。
