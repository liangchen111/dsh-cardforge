# 制卡工具（forge）

给 [ElecKoi](https://github.com/eleckoi/ElecKoi)（PC + Android）做的一套**制卡工具**：
从零开一张卡、改现有卡、校验、挂模块、换皮肤、组装卡内界面、打包、和酒馆（SillyTavern）来回搬。

三条约定：

- **`spec.yaml` 是唯一真相，`card.json` 是派生物。只手改 spec。**
- **内容住 `source/`，界面住 `hud/`**，改哪层动哪层。
- **颜色住 `hud/主题.css`，版式住 `hud/hud.css`**，换皮肤碰不到机制，改机制不会把配色弄丢。

依赖只有一条：`PyYAML`，其余全是标准库（Python ≥ 3.9）。

## 装法

这是个**文件夹工具**：`forge.py`、`forge/`、`assets/`、`samples/`、`向导/` 要待在一起。

```
python forge.py <命令>      # ① 直接跑（最省事）

python -m forge <命令>      # ② 当模块跑（等同 ①，给不想记文件名的人）

pip install -e .            # ③ 装成 `forge` 命令（推荐）
forge <命令>
```

> **为什么必须 `-e`**：仓库里 CLI 的**实体**是根目录的 `forge.py`，而 `forge/` 是它的内核包 ——
> **两个同名**。普通 `pip install .` 只装走包、装不走 `forge.py`，`forge` 命令就找不到它；
> `-e` 把整个文件夹留在原地，命令和资源（`assets/`、`samples/`、`向导/`）都还在。
> 也正因为同名，`import forge` 拿到的是内核包 —— `forge/cli.py` 只做一件事：找到仓库根，把 `forge.py` 当脚本跑起来。

## 给别人怎么用（四种交法，别搞混）

**预设和角色卡只认本机文件**（安装来源只有「内建」和「用户导入」两种，没有网络装载通道）。
**插件不一样 —— 包名、Git 地址、压缩包、本地绝对路径四种写法都吃**；这个仓库**本身就是一只能贴链接安装的插件**（根目录的 `package.json` ＋ `cordis.patch.yml`）。

| 对方想要什么 | 给他什么 | 他怎么用 |
|---|---|---|
| 做卡时被 AI 陪着 | `向导/制卡助手/成品/制卡助手.preset.png` | ElecKoi →「预设管理器」→「导入预设」→ **分类必须选「创作预设」**（选错会提示「这不是创作预设。」） |
| 在对话里问「怎么建卡」 | `向导/制卡助手/成品/制卡助手.card.png` | 当普通角色卡导入（手机端「导入角色」也认这张） |
| 自己要做卡 | 仓库链接或出厂 zip | 解压后 `python forge.py plan` 开工；也可以 `pip install -e .` |
| 想常驻 ElecKoi 界面 | 插件名 **`dsh-cardforge`** | 侧栏「插件」→「添加插件」→ 贴包名 `dsh-cardforge` → 安装 → **重启 ElecKoi**（名字还没同步过去时，贴仓库地址 `https://github.com/liangchen111/dsh-cardforge` 一样能装） |

四条容易踩的：

- **装完必须重启 ElecKoi**（插件只在宿主启动时载入，不重启不生效）。**装插件顺带把预设也装好了**：
  插件看有没有「制卡助手」这个创作预设，没有就自动导入，有就一个字不写；只有当前创作预设
  还是官方默认那个时才切过去 —— 你自己挑过的一律不动。关掉：`installPreset` / `activatePreset`。
  预设存在 ElecKoi 自己的数据里，**卸载插件不会带走它**（不自动删是因为你可能改过它）。
- **「找不到 Python」不用配。** 配置里 `python` 留空＝自动找：先看 `FORGE_PYTHON`，再挨个试常见位置
  与 `PATH`，**真跑一次 `import yaml`**，谁能跑通用谁 —— Windows 上「装了 Python」不等于它在 `PATH` 上。
  都找不到会告诉你它找过哪些地方；机器上有好几个 Python 挑错了，才需要写死完整路径。
- **卡做在哪个目录也不用每次说。** `cwd` 留空＝`<你的用户目录>\Documents\ElecKoi卡库`（没有就自动建）；
  调用时给了 `cwd` 就听参数的（参数 > 配置 > 默认）。
- **点安装报「连接 GitHub 超时」＝这台机器到 github.com 不通。** 预检只有 5 秒（`git ls-remote`），
  直连实测 21 秒都连不上。① 给 git 配代理：
  `git config --global http.https://github.com/.proxy http://127.0.0.1:你的代理端口`；
  ② 或点「试试其他方式」，改成贴**本机插件目录的绝对路径**（出厂包里 `插件\制卡工坊` 那个目录），完全不碰网络。

**插件细说看两份文档**：[`文档/插件-DSH.md`](文档/插件-DSH.md)（它是什么形式的插件 · 怎么装 · 五个配置键 · 怎么用 · 在纯 DSH 里怎么活）·
[`文档/插件-ElecKoi.md`](文档/插件-ElecKoi.md)（装进电子爱多出来的那件事：自动装创作预设 · 验收三条 · 手动兜底两条路）。

那两个 PNG 是**可直接分发的单文件**，对方不需要装 Python、不需要克隆仓库。要改内容再重新导出：

```
python forge.py coach                      # 重新生成规程 + 向导卡源
python forge.py preset 向导/制卡助手/source/制卡助手.spec.yaml --png
python forge.py png    向导/制卡助手/source/制卡助手.spec.yaml
```

## 三分钟上手

```
python forge.py plan                                   # ① 开工先落一份规划书（九节空模板 —— 填满再动手）
python forge.py new   我的世界                        # 开一张新卡（内容层 + 界面层一起生成）
python forge.py check 我的世界                         # 体检（含界面规矩、皮肤可读性）
python forge.py hud   我的世界 --写回                   # 改过 hud/ 之后重新组装界面
python forge.py build 我的世界/source/我的世界.spec.yaml 我的世界/成品/我的世界.card.json

python forge.py new   我的世界 --模块 骰子,备份        # 顺手接两块现成机制（条目+界面一起接）
python forge.py drop  备份 我的世界/source/我的世界.spec.yaml   # 后悔了就撤，接之前的样子还在账本里
python forge.py theme 墨夜 我的世界                     # 换皮肤（换完记得再 hud 一次）
python forge.py theme --巡览 我的世界                   # 五套皮肤摆一起对比
python forge.py bundle 我的世界                        # 打成一个工程包（分发 / 备份）
python forge.py import 我的世界.工程包.zip --到 同事的卡   # 收包：落到本地，成一张能接着改的工程
python forge.py new    深夜便利店 --从 同事的卡.card.json   # 接手现成的卡：界面层照抄骨架，内容层用它的
python forge.py theme  --导出 我的世界                   # 把这张卡调好的配色导成一份皮肤文件（可发人）
python forge.py png    我的世界/成品/我的世界.card.json  # 出卡图（.card.png，ElecKoi 手机端「导入角色」认的就是它）
python forge.py preset 我的世界/成品/我的世界.card.json --png  # 出「创作预设」（.preset.json / .preset.png）
python forge.py lint   我的世界/成品/我的世界.card.json  # 正文体检（防八股）：只查句式骨架，不查词
python forge.py lint   -                               # 刚写完一轮？直接从标准输入丢进去查
```

往卡里**加东西**（以前只能改已有的，现在能从无到有）：

```
python forge.py entry 我的世界 --新 "夜里的酒馆" --模板 关键词 --关键词 酒馆,打听
python forge.py entry 我的世界 --列                     # 看看条目长什么样
python forge.py entry 我的世界 --看 "核心 · 世界总纲"     # 读一条的全貌：正文全文 / 关键词 / 提示 / 触发…
python forge.py entry 我的世界 --改 "核心 · 世界总纲" --正文@世界总纲.txt   # 长正文写成文件再 @ 引
python forge.py group 我的世界 --新 支线                # 分个组
python forge.py var   我的世界 --新 玩家.声望 --类型 number --初值 0   # 变量三处一次写齐
python forge.py regex 我的世界 --新 "清理变量" --模式 '…' --替换 '…'   # 加正则（Git Bash 里先 export MSYS_NO_PATHCONV=1）
python forge.py opener 我的世界 --正文@开场白.txt       # 换开场白（末尾那三个零宽标记工具负责）
python forge.py opener 别人给的卡 --正文@开场白.txt      # 只有内容层的工程也认
python forge.py trash 我的世界                          # 删错了？都在这儿，--还原 1 放回最近一条
```

看全部命令：`python forge.py`

**在「不许删、不许改名」的环境里跑**（比如 ElecKoi 里的 AI 直接跑命令）：任何命令后面加 `--沙箱`，
或先 `export FORGE_SANDBOX=1`。forge 会切成「只创建、只覆盖」—— 落盘直接覆盖目标、回收站改用墓碑、
撤皮肤写空壳。代价是丢掉原子落盘，**能不用就不用**（自检第 42 项盯着这条）。

> 建议用一个装好 PyYAML 的独立 Python 环境（`venv` / `conda` 都行），别拿系统 Python 直接跑。

## 制卡向导（`coach`）—— 教 AI 怎么做卡

上面那些命令是**给你**用的。想让 AI 替你开新卡，缺的不是命令，是**一份 AI 读得懂的制卡规程**：

```
python forge.py coach            # 默认出到 ./向导/（--到 <目录> 换地方）
```

一份内容，两个出口：

| 产出 | 给谁 | 怎么用 |
|---|---|---|
| `向导/AI制卡规程.md` | 电脑上的 AI（Claude Code / Codex / Cursor 这类） | 丢进对话，说「照这个给我做一张卡」 |
| `向导/SKILL.md` | 同上，带 frontmatter | 拷进技能目录当技能用（如 `~/.claude/skills/eleckoi-card-maker/`）；规程更新后不用重装 |
| `向导/制卡助手/成品/制卡助手.card.json` | **ElecKoi 里的 AI**（陪你聊天那个） | 导入挂上：它变成制卡师，在对话里一层层访谈你 |

两份出口共用同一套**方法论九篇**（机制 / 条目触发 / 预算 / 世界 / 故事 / 角色 / 写法 / 变量 / 界面）＋
一章**红线**（会被 ElecKoi 静默吃掉的写法）。

**不想一次读完整份规程**（一万七千字，塞进上下文既贵又冲淡重点）：`guide` 先出目录，再按需取一段 ——

```
python forge.py guide                 # 目录：有哪些节、哪些篇、哪几篇必读、有哪几段「对话」
python forge.py guide --节 三          # 一节（一 开工流程 / 六 验收标准 / 九 红线 …）
python forge.py guide --篇 预算        # 一篇方法论 · `--对话 访谈` 一段在对话里做卡 · `--全文` 整份
```

认不出的名字**当场报错并列出全部候选**，撞名的报「不止一个」让你写全，绝不静默挑一个。
装在 ElecKoi 里的插件就是靠这条自己把知识取到手，不必等人把规程贴进对话。

向导卡**自己就是范例**：由 `coach` 生成，所以它自己也体检 0 错、常驻字数守在预算内。

## 一次落成（`make`）—— 想清楚了就别来回跑

`new` → `group` → `entry` × N → `var` → `regex` → `opener` → `build` → `check` 是七八次进程启动。
人用不累，**AI 在对话里用就贵**：每次调用都是一整轮。所以想清楚之后，一次落成：

```bash
python forge.py make --示例        # 先打出一张真能开的完整卡稿（长夜便利店）—— 照着改
python forge.py make --模板        # 或者只要骨架：有哪些键、怎么缩进
python forge.py make 我的卡.yaml   # 一趟：建工程+写条目+加变量正则+换开场白+出成品+体检
```

`--模板` 只回答「有哪些键」，`--示例` 连「**话该写多细、哪句放常驻、哪句放关键词**」一起示范 ——
AI 最容易失手的不是键名，是「写多细算够」，一份好样板比十条规则管用。

稿子写的是**这张卡该长什么样**，不是「先做这步再做那步」：

- **条目按标题认人** —— 卡里已有同名的就改它，没有才新建。想清掉骨架自带、稿里没提到的条目，
  写一行 `清空条目: true`；想删掉某一条，写 `删: true`。
- **给已有条目写 `模板:` / `分组:` 也真生效**（换档与挪组都会落下去）；分组 / 变量对象缺了自动补。
- **全程在临时目录里做，全绿了才整棵拷到目标位置** —— 稿子有毛病时目标位置**一个字都不会被写**，
  静态能查的（模板名 / 类型 / 值域会不会被静默降级）一次报全。
- `--试` 只验证不出；`--覆盖` 才允许把已有同名工程照稿重落。加 `--沙箱` 照样一趟落成。

**规程是「走过一遍」的，不是「想出来」的。** 它被拿去做过**五轮盲跑**：不看内部代码的 AI 只拿规程
照章施工，卡在哪就记下来。第一轮「从零建卡」修回 15 处，第二轮「接手别人给的卡」挖出 10 处，
第三轮补上了缺的搬运命令（`new <卡名> --从 <卡>`），第五轮端到端做出 11 条目 / 14 变量 / 6 对象、`check` 0 错。

## 路线图

|  | 是什么 | 状态 |
|---|---|---|
| **A · 离线工程链**（就是本工具） | `forge.py` 命令 + 规程，AI 照着跑，最后交出**卡** | **已可用** |
| **B · 卡内 HUD** | 卡自带的页面内界面（面板 / 悬浮球 / 建卡器），靠一条正则送进宿主页 | 骨架与模块齐了，具体卡自己长 |
| **C · ElecKoi 原生插件** | 在 ElecKoi 里给 AI 一个 `cardforge` 工具，直接跑 `forge.py` | **已发版**：`插件/制卡工坊/`，装法见上表第 4 行 |

**为什么插件比「让 AI 用自带命令行工具」强**：ElecKoi 自己的命令行工具跑在**受限令牌沙箱**里
（读得到、写得进，但**不许删、不许改名**，`WinError 5`），而 forge 每次落盘都靠改名（`os.replace` /
`os.rename` / 回收站是「移动」）。**宿主插件起的子进程不受那层沙箱管** —— 原子落盘、改名、回收站全都回来了。
一句话分工：**能用插件就用插件（全功能）；只能用命令行工具就加 `--沙箱`（丢掉原子落盘，但能干活）。**

## 一张卡工程长什么样

```
我的世界/
  source/我的世界.spec.yaml     内容层：世界观、条目、变量、正则   ← 改内容只改这里
  模块账本.json                  接过哪些机制、并进来了什么          ← 撤模块靠它，别手改
  .forge/回收站/                 删掉的条目 / 变量 / 正则存这儿        ← 可逐项还原
  hud/                          界面层：建卡器 / 面板 / 悬浮球     ← 改外观只改这里
    hud.conf.json                 卡名、id 前缀、HUD 全局名、要接几条正则、现在用哪套皮肤
    hud.core.js                   通用核心（把变量树画成面板 + 建卡器 + 悬浮球）
    hud.css                       版式（一个颜色都不写死，全从 --hud-* 槽取）
    主题.css                      皮肤（只有颜色槽覆盖；由 forge theme 写）  ← 可没有
    view_create.html              建卡器那一块的骨架
    view_card.html                面板那一块的骨架
    模块/<名>/<名>.js|.css        按需挂上的模块（悬停的机制，撤掉就删目录）
  测试/test_core.js             HUD 纯函数单测（node 跑，新卡自带）
  成品/我的世界.card.json        交付物（导入 ElecKoi 的就是它）
  文档/                          手册与索引（bundle 时生成）
  怎么开工.md                    这个工程怎么用
  预览.html                      界面在浏览器里的样子（forge hud 产出）
  皮肤巡览.html                  五套皮肤的对照图（forge theme --巡览 产出）
```

**hud.core.js 不含任何世界观内容**：你往 `variables` 里加一栏，面板上就多一行，不用改代码。
换卡只动 `hud.conf.json`。

## 护城河是什么

**九条，每条都对应一类「填了不报错、但事实上没生效」的坑**（细目与例证见 `文档/使用说明.md` §五）：

|  | 一句话 |
|---|---|
| 一 | **真值域表** —— ElecKoi 对不认识的字段值**静默降级**，本工具把反编译取证出来的真值域表变成了会拦截的代码（`forge.py domains`） |
| 二 | **变量三处同步** —— `objects` / `initial_state` / `schema_code` 少任何一处都不报错，写入会被静默丢掉；`check` 会对一遍，`var --对齐` 能补回来 |
| 二·补 | **形状不猜** —— `initial_state` 里是几层对象**是卡自己写的**：对得上就写，对不上当场说是哪一格挡着，绝不猜着塞 |
| 三 | **界面层边界守则** —— HUD 整段注进宿主页面，`check` 逐文件扫三反引号 / `<!--` / `</script` / `position:fixed`，且 **CSS 每个选择器必须带 `.hud` 前缀** |
| 四 | **模块可撤** —— 模块是**覆盖**进 spec 的，所以每接一个都把「原来长什么样」存进账本；`forge drop` 才能精确撤回。**你手写进 spec 的东西，工具一个字都不动** |
| 五 | **换皮肤不碰机制** —— 颜色全在 `--hud-*` 槽里，主题只写槽；外带对比度体检（按宿主纯白 / 近黑两路各算一遍取更差） |
| 六 | **双向无损** —— 转酒馆时把变量、分组、未映射字段、条目 id 与顺序全存进 `extensions`，回来时走回迁路径取回；艾瑟兰 2.5MB 实卡往返语义完全一致 |
| 七 | **能力缺口的诚实交代** —— 酒馆没有「由 AI 自己选读」这一档，转过去的条目会变成「永不自动触发」，工具**点数并说清根因**，不假装成功 |
| 八 | **值域在写入那一刻就拦下** —— 会静默降级的字段当场拒收，并写明「会被降级成什么」，让人没机会「填了不生效」 |
| 九 | **工程层也要对得上** —— 模块目录没登记 / 账本没记 / 改了 spec 没重出成品 / `hud/` 没写回 spec，这四种错**一个都不报错**；`check` 照着 `PROJ-*` 逐条查，组装时也会主动说一句 |
