## 2. 市场已经在用的「防八股」——作者问的那件事，先有实证

> ⚠️ **作者 2026-10-15 追加否决（m00367 原话：「别抄这个，这个是我朋友的，不太好，你去联网搜搜这方面的咋搞」）**：
> 下面这份预设里那条 `<禁词表>` **是作者朋友的作品，作者已判定不适合当样板**。
> 本文保留它只有三个用途：
> ① 证明「预设里确实有人在做防八股」（生态事实）；
> ② 证明「**禁令放在指令层、而不是替换层**」这个**结构选择**在市场上真实存在；
> ③ 当**反面参照** —— 「形容词词表 + 句式混在一张表里 + 禁数字」正是我们**不采用**的那一类。
> ⇒ **推荐做法一律以 §6.1 的调研结论与 §5 的四层机制为准；§2 只当现场观察，不当模板。**

### 2.1 真实预设（不是论文、不是理想设计）

`_preset_dump\preset_report.txt:194-214`，条目 `[4] 禁词表`（`kind=normal`、`trigger_mode='always'`、
`position='insert_point_1'`、`content strlen=166`），原文逐字：

```
<禁词表>
 - 严禁使用任何带"三"的数字和词汇以及大量量词聚集，除非"用户最新输入"否则严禁使用。
 - 严禁使用"不是……而是……"、"与其说……不如说"、"看似……其实"的句式极其变体。
 - 严禁使用"她……/他的情绪……"的情绪比喻语句。
 - 严禁大量描写、比喻文字、对举句、单字动词、无宾语、短句应答。
</禁词表>
```

★ **四条里三条是「句式模板」，不是形容词词表。** 这是关键判据：

- 「不是……而是……／与其说……不如说／看似……其实」——**可穷举、可正则、低误报**（它们是结构，不是词）。
- 「带『三』的数字／量词聚集」——**可数**（结构性）。
- 「她……／他的情绪……」——**命名了一个具体句法**（主语+情绪名词），不是泛泛的「别写情绪」。

⇒ **结论修正**：我在《拆解》§五 里说「不要词表化」，**要收窄成「不要形容词词表，要句式模板表」**。
`极其 / 的特质 / 沙哑 / 一丝 / 不容置疑地` 那类（创世回廊 5.2 的做法）才是高误报的那种；
`不是…而是…` 这类**是能当门禁的**。

### 2.2 它把禁令放在「指令层」而不是「替换层」

这条 `禁词表` 是 **`trigger_mode='always'` 的普通条目**，插在 `insert_point_1`（写作指导位），
**没有做成 regex 替换**。同一份预设的确有 4 条 `regex_rules`，但用途完全不同（`:333-336`）：

| 正则 | 用途 | 字段 |
|---|---|---|
| `时间条修改` | `<time>` → `$1\|时间$2\|$3` | `targets:["AiOutput"]` · **`prompt_only:true`** · `order:0` |
| `时间条美化` | `<time>` → 整段 HTML 状态栏 | 同上（纯展示产物，长 HTML） |
| `选项卡屏蔽` | `<option>` 块 → 空串 | `prompt_only:true` · `order:2` |
| `选项卡美化` | `<option>` 块 → HTML 选项卡 | 同上 |

⇒ **文风治理走指令，标签→界面走替换，两条线不混。** 这条分工对我们直接可用（艾瑟兰的
`regex_rules` 18 条里 15 条是 `display_only`，正是后半条；前半条——把文风禁令写进条目——目前只在常驻里零散存在）。

### 2.3 它的「写作指导」长什么样（分节 + 可核验祈使句）

`[3] 写作指导`（`content strlen=483`，`:142-172`）分六节：`# 对白` `# 内心戏` `# 描写` `# 人称` `# 描写范围` `# 字数要求`。
每条都是**可当场核验的祈使句**，例如：「人物的对白总是省略发言人的」「对白总是交替进行的严禁将一个人物的对白分成多段话」
「内心戏的内容严禁在未说明的情况下让{{user}}得知」「**字数不少于1500字**」。

★ 这与《形态判定》§5 已立的第①条（判例句优于原则）和第②条（阈值优于形容词）**是同一件事**，
而市场样本证明它已经跑通了一年以上。⇒ 不是我们发明的，是**要固化进规程的**。

### 2.4 它的 `usage_instructions` 本身就是一张「条目地图」

`:7-22`（392 字）把条目按用途分成四类并各给一句职责：「**写作指导**：管控着文章的整体节奏……
**禁词表**：管控着八股文的出现频率，删八股文相关可以加在此处。**参考文风**：负责管控文章参考书籍……
**其他格式**：此处允许添加各种小组件……」。
另外还借了图标语义：**「盾牌」＝不建议更改、「星星」＝可自由更改、「纸条」＝预填充项严禁修改**（`:12`），
并**明说自己的短板**：「此预设处于早期阶段**未完全解决文风问题**」（`:12`）。

⇒ 两条可借：① 预设的 `usageInstructions` 当**条目地图 + 可改性说明**（8,000 字上限，很宽裕）；
② **作者自曝短板**——这条在制卡助手身上同样该做（AI 才会知道哪里该问人）。

### 2.5 `roleplay_plan.steps`：把「想」也变成规程

`:38-45` 三步思维模板（`</think>` 内），第一步「先调工具读设定，再勾计划」、第二步一张情景清单
（时间/地点/角色/关系 → 回顾历史**不能重复高度近似的结构** → 检查剧情 bug 或**全知现象** → 按核心风格构思），
第三步「思考完再外部构建 response」。并且三步都带同一条 NOTE：
「**冲突或不明确的指示以最新优先，快速决策**」「**必须确保外部构建，不在内部思考中创作正文**」。

★ 注意第二步那句「**不能重复高度近似的结构**」——这是**市场自己给出的「防重复/防模板化」机制**，
和句式禁令是同族但不同层（一个管句子，一个管情节）。我们的《故事推动引擎》可以照这个位置加一条。

## 3. 6 张示例卡证明的另一半：八股首先是**行为**问题

本地跨卡归纳（`（共性）示例卡世界结构对比.md`）给出的最硬共识，不是文风：

| 机制 | 出现率 | 说明 |
|---|---|---|
| 地理／空间锚 | **7/7** | 没有一张无地理卡 |
| ★ **NPC 稳定性／独立性约束** | **6/7** | **最普遍的设计共识** —— 防的就是「NPC 写成布景或刻板符号」 |
| 长期资料管理 | 6/7 | 分内嵌长文／内联结构化库／向量记忆／序号化账本／全外部五种路线 |
| 数值·进度·抽卡 | 5/7 | 艾瑟兰**刻意不做**（反数值），保留 |
| 留白／信息管控 | 3/7 | 艾瑟兰是这一档的最强项（另册矛盾史料法） |

⇒ **「防八股」在制卡助手里必须扩成两层**：

- **文风层**（句式模板禁令 + 指导分节 + 字数阈值）——见 §2；
- **行为层**（NPC 不许变布景／不许全知／不许凭空知情／情节不许重复高度近似的结构）——
  这一层市场是靠**条目里的硬约束 + 每轮强制动作**解决的，不是靠文风技巧。

行为层的现成机制（均来自本地归纳，二手）：
`（评估）示例卡共性 vs 艾瑟兰.md:37-48` 给的五个可对标本里，三个直接是行为约束：
① **长线记忆结构化召回 + 报数自检**（把「正在走的事」从只追加字符串升级为带序号条目，
每轮召回「近期 2–3 件／早期 1 件」，末尾报 `〔账〕共 N 件，本轮提到 M 件`）；
② **NPC「每轮下一步动作」强制**（每轮收尾给在场每个有名有姓者各写一句下一步动作；**写不出来的，该人本轮应退场**）；
③ **未回收伏笔追踪**（`〔线〕X ｜ 埋于 N 轮前 ｜ 待收`，每隔几轮让一条从边角再露一次，不解释）。

## 4. TavernWeave 里可借的工程机制（只列判据，不搬文本）

- **路由三件套**：`description` 里同时写「做什么 / 何时用（含中文触发词）/ **不要用它做什么、交给谁**」。
- **知识 vs 动作分家**：`references/` 是按需读的判据，`scripts/` 是可确定性执行的动作，`tests/` 只测脚本不测内容质量（它自己承认这一点）。
- **资料库按需读取**：README 原文「安装一次不等于每轮塞入整个资料库」——与艾瑟兰总纲同一句话。
- **安装核验**：装完核 `22/22`，且「文件匹配」与「客户端实际加载」**分两次检查**。
- **全局规则单列执行门**：不得因「推荐」静默写入。
- **能力核验留痕**：自评 + 七章报告 + append-only 履历；`code-quality-workflow` 的 Finish Mode。
- **明文拒绝用词表替代判断**（`rewrite-natural-prose\SKILL.md:25`）——注意它拒的是**判断被词表替代**，
  **不拒**「把可枚举的句式模板写成禁令」。我们采用后者时口径要写清，免得自相矛盾。

不借：入口栈的前三层（Host Front Door / Soul 人格 / 脑暴编排）——单卡专用工具加人格层只会稀释路由、加每轮成本。

## 5. 融合后的形态：三件事接成一条线（我们的特色）

| 层 | 机制 | 落在哪 | 能不能拦 |
|---|---|---|---|
| **A 指令层** | 文风禁令用**句式模板**（不是形容词词表）＋ 写作指导分节（对白／内心／描写／人称／范围／字数）＋ 每条带阈值 | `forge\coach.py` 的经验源 → 渲染进预设条目的 `always` 段 | 不能自动拦，但可被 C 层抽查 |
| **B 工具层** | 结构断言：条目字数区间 · 常驻字数只降不涨 · 标题即路径 · 零字目录 · 每段四件套 · 口语钩子句占比 · **句式模板命中数** | 新增 `forge\prose_lint.py`（或并进 `check`），挂进现有门禁 | ✅ 能拦（rc≠0） |
| **C 流程层** | 行为约束：NPC 每轮下一步动作强制 · 未收的线追踪 · 不许凭空知情 · 情节不许重复近似结构 · 每轮报数自检 | 经验源里的**规程条款**（写进每一张新卡，而不是只写在艾瑟兰里） | 半自动（可查「有没有这一节」） |
| **D 授权层** | 三档授权（轻润色／结构改写／深度重写）＋ 保护面清单（宏 `{{user}}`、变量路径、EJS、正则、JSON 键、ID、代码、原文引用逐字保留）＋ 改完跑结构检查 | 规程 + `rewrite` 命令（若要） | ✅ 保护面可自动核 |

**特色在哪（相对三家都在做的）**：别人要么只做 A（真实预设）、要么只做 A+D（TavernWeave 的文风 skill）、
要么只做 C（示例卡）。**把 A/B/C/D 接成一条「改完必须过门禁」的流水线，并且经验源只有一份、产物多种**——
这是我们自己的形态，也是艾瑟兰那套「门禁 + 台账 + 单一真源」直接平移过来的。

**★ D 层的形状由证据定死，不是风格选择**（2026-10-15 第三轮调研）：改写会磨平作者声音
（Nature Human Behaviour 2026：88 万+ 文本改写后复杂度变异降 21–50%、作者特征可辨识度降 6 个百分点）
⇒ 所以 D 层**不是「替作者改文风」**，而是 **①先锚定作者本人 3–5 段亲笔原文当正例**（MASH 那条路，ACL Findings 2026）·
**②只改结构、不改声音** · **③保护面逐字保留**。**禁词表最多当「写作时提示物」，不做验收判据**
（依据：上一条 ＋ TextPulse 阈值 0.40 会同时误报 39% 人类文本）。

## 6. 调研回填（联网 + 本机一手）

### 6.1 去 AI 味／防八股（已回）

**① 最完整的「AI 味」目录是维基百科的 [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)**
（本机取不到，镜像：[signs-of-ai-writing.md](https://github.com/Dannykkh/skill-olympus/blob/master/skills/writing-clearly-and-concisely/signs-of-ai-writing.md)）。
它的核心机制一句话可以借走：**「回归均值」——把具体事实换成通用好评**。
它的**节名本身就＝检查项**：重要性膨胀（symbolism/legacy/importance）· AI 高频词 · **否定式排比（Not only…but…）** ·
**rule of three（三连）** · 模糊归因 · **同义轮换（excessive synonym variance）** · 虚假范围 ·
**破折号滥用** · 粗体滥用 · 行内标题式竖排列表 · emoji · 标题大小写 · 总结与结论段 · 「挑战与展望」式收尾 · 面向用户说的话。

这是「**别拿词表当判据**」的官方背书 —— 与 §2.1 的收窄口径完全一致。

**② 可实施的工程范式：`anti-ai-slop` 的四道闸**（[misbahsy/anti-ai-slop](https://github.com/misbahsy/anti-ai-slop)）
—— 这是目前看到最值得照搬的**流程形状**：

1. **sanitize**：删零宽字符与双向控制符；
2. **linter**：正则 + 计数，**100 分制固定扣分**，跳过代码与引文，**≥90 且无严重项才过**，频率型规则报「次数 + 速率 + 行号」；
3. **第二读者 agent**：只看「原文 + 改稿」，**不给它改稿理由**，专抓编造事实／增删因果／同义轮换／意义走样；
4. **跨厂 panel**（多模型投票）。

配两条硬约束：**不许编造 · 不许改原意**；失败**最多回炉 2 次**，仍不解决就**列出来不藏**；
授权两档：**scrub（重写）／audit（只标记不改）**，且 audit 的硬边界是「**只报现象，不判作者**」（「这是 AI 写的」永不出口）。

**③ 阈值：什么能当门禁、什么不能**（一手来源见括号）

- ★ **句长变异系数（CV）是群体信号，不是个体判决**：[TextPulse/Zenodo 工作论文（60,779 对同文改写）](https://zenodo.org/records/22033063)
  测出人类 CV 均值 **0.449**、AI 改写 **0.376**，**79.3% 变平**；DeepSeek 最狠（−0.234／98.5%）、Grok 最轻（−0.032），**模型间差 8 倍**。

  ⇒ 中文卡要**算段内句长 CV**，不是算全文句长 CV。
- **别迷信检测器**：重度 LLM 用户判「这是 AI 写的」约 90% 准（＝误伤 1/10），不用 LLM 者接近随机；
  检测器对改写与空格变动脆弱；**GPTZero 2023 年秋就弃用了 perplexity+burstiness** 转分类器。
  ⇒ **perplexity/GLTR 不做门禁。**
- **不要判「作者归属」**：改写即逃逸、误报伤作者。我们要的是**文风质量门禁**，不是「这是不是 AI 写的」。

- 触发键与标题**不进上下文** ⇒ **每条 `content` 必须自包含**（与艾瑟兰「门」机制同构：命中即可独立读懂）。
- `order` 越大越靠近上下文末尾；**constant 先占预算，再按 order 排**；预算耗尽即停
  ⇒ **「常驻只降不涨」在上游是官方机制，不只是我们的纪律**。
- ★ **`Match whole words` 官方明说对不用空格分词的语言（日语、中文）有害，建议关掉** —— **中文卡最主要的误触发源**；
  另 `\x01` 前缀（v1.12.6+）可按角色名/用户名匹配。
- **递归三开关**：Non-recursable／Prevent further recursion／Delay until recursion ＋ `Max Recursion Steps` 限步；Min Activations 与 Max Recursion Steps 互斥。
- Outlet 官方 caveat：条目内不能写 `{{outlet::}}`、不能嵌套、角色卡字段不能展开 outlet（**求值顺序会死循环**）。
- CCv3 的 `@@` 装饰器（`@@depth`/`@@role`/`@@position`…）是同语义的**可移植层**，ST 本体不实现。
- ★ **向量匹配官方注明「结果不可预测，要确定性就用关键词」** ⇒ 与艾瑟兰「明文禁止 embedding／向量库」完全一致（**上游背书**）。

### 6.4 把手艺做成 agent 可执行技能（已回，依据 Anthropic/Agent Skills 一手）

**三份物件的边界**（这是整套体系的骨架）：
**规则文件＝每轮都真需要且必须极短的**（`AGENTS.md` 自称「README for agents」，无必填字段，嵌套时离被改文件最近者胜，且「用户对话中的显式提示覆盖一切」）；
**skill＝有触发条件的成套手法**；**脚本＝确定性、要反复跑、要能当门禁**。
一手依据：Anthropic 说脚本的价值是「because code is deterministic, this workflow is consistent and repeatable」；
工具则是「a contract between deterministic systems and non-deterministic agents」，所以**少而精、别包 API**（该做 `search_contacts` 不做 `list_contacts`）。

**硬契约**（[specification](https://agentskills.io/specification)）：`SKILL.md` + YAML frontmatter，`name`（≤64，小写字母数字连字符，**须等于目录名**）与 `description`（≤1024）必填；
`compatibility`/`metadata`/`allowed-tools`（**实验性，各实现支持不一**）可选；目录约定 `scripts/`／`references/`／`assets/`，**引用只允许一层深**；官方校验器 `skills-ref validate ./my-skill`。

**渐进披露是三级**：元数据（~100 token，**启动即载入全部 skill**）→ 正文（<500 行、<5000 token，激活时载）→ 资源（按需载）。

★ **条件化引用**（最容易漏的一条）：「Read `references/api-errors.md` if the API returns a non-200 status code」比「see references/ for details」有用得多；
把说明放进 `references/` 却在正文不写触发条件 ⇒ **agent 根本不知道要读**（[best-practices](https://agentskills.io/skill-creation/best-practices)）。
⇒ 我们 29 条子命令要逐条写「哪一步读规程的哪一节」，禁写「详见规程」。

★ **单真源 ＋ 渲染 ＋ 验证**：业界标准是「生成器脚本 + CI 里重跑后 `diff --exit-code`」
（范式见 [verify-codegen.sh](https://apache.googlesource.com/submarine/+/f621a32379b5af8dee77d242cd2e2808db1a040d/submarine-cloud/hack/verify-codegen.sh)）
⇒ `forge.py render` 与 `render --check`，把「三份副本会各自漂移」变成机器能拦的红灯。

★ **门禁与反假绿**（[Evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills)）：
用例 `evals/evals.json` ＝ prompt + expected_output；**每条跑两遍**（with skill / without skill，改版时基线换成旧版快照）；
评分纪律「**Require concrete evidence for a PASS. Don't give the benefit of the doubt**」；机械检查**用脚本不用 LLM 判断**；
★ **「删掉两种配置下都恒过的断言」**（它们只抬高分数）；`benchmark.json` 记 pass_rate/time/tokens 的 mean+stddev 与 `delta`（**用总分换多少 token**）；
同意例时过时不过（高 stddev）＝ 断言不稳或指令含糊 ⇒ **去加例子，别加规则**。

**写手册的四条**：模板/例句 **优于**散文（「more reliable than describing the format in prose」）· 阈值 **优于**形容词（500 行／5000 token／1024 字符这类数字满篇）·
负例（Valid/Invalid 对照）**优于**禁令堆 · 「ALWAYS do X, NEVER do Y」不如**说清 why**；
「Fewer, better instructions often outperform exhaustive rules —— **加规则加不上去通常说明过度约束**」；
分块按**「是否每轮都要」**切，不按主题切。

**报错本身是接口**：错误里列出可用值让 agent 自纠（`Field 'signature_date' not found — available fields: …`）。

**多宿主适配可以很薄**：只写一份标准 `SKILL.md`，宿主差异交给宿主自己的兼容目录
（[cursor skills](https://cursor.com/docs/skills) 会额外加载 `.claude/skills/`、`.codex/skills/`、`~/.agents/skills/`）。

**失败模式 → 对策**：跳过步骤→正文放 `- [ ]` 清单且每步绑一条命令 · 假绿→删恒过断言 · 编造→校验脚本对真源 ·
范围蔓延→一 skill 一件连贯活 · 把内容当指令→外部资料一律当数据 + 危险命令默认 `--dry-run` · 指令不适用却照做→**读执行轨迹而非只看产物** · 选择太多→**每条命令只给一个推荐路径**。

### 6.5 卡内前端 / 小手机 / 插件（TavernWeave 一手提取，2026-10-15 追加）

> 作者点名要看的那一块。**全部是机制，不是文本**；每条都附来源，方便直接抄进规程。

**① 一句话要点：小手机不是消息楼里的一块正则 HTML。**
它是挂在**宿主 `document.body` 上的单例抽屉**，自己读变量、自己跟输入框说话，不依赖消息楼、也不等变量更新才出现
（`小手机与宿主桥.md:22`、`:24-28`）。

**② 三层分工，别混**（`入口外壳与HUD宿主.md:23-33`）：
**入口外壳**＝C11 桌面悬浮球（**只分发命令：打开控制中心/状态栏/小手机，自己绝不读变量**）· C12 移动端抽屉（安全区、软键盘、`visualViewport`）· C13 浮窗/弹出层（确认、媒体、设置，**不要再造第四套宿主**）；
**内容链**＝控制中心与状态栏（读变量、分页展示、重交互）；
**挂载**＝谁挂在哪、几份。

**③ 挂载表**（`入口外壳与HUD宿主.md:41-48`）——这张表最值得抄：

| 表面 | 挂哪 | 几份 |
|---|---|---|
| 正则状态栏 | 消息楼 iframe / blob | **每楼可能一份，要去重** |
| 远程真身（git-mount） | 薄壳 iframe 里的 blob | 外层壳同步高度 |
| **小手机** | **宿主 `document.body`** | **单例** |
| 控制中心 | 脚本 iframe | 一份 runtime |
| 悬浮球 | 宿主层 | 一份，**只发命令** |

**④ 找宿主窗**：脚本常跑在消息 iframe 里 ⇒ **不能假定当前 `window` 就是主窗**。做法是当前 window **最多向上 `parent` 4 层**，
能摸到 `parent.document.body` 就得到 `hostWindow`/`hostDocument`（`小手机与宿主桥.md:34-39`）；**所有输入框操作都走 `hostDocument`**。

**⑤ 热重载**：挂新 runtime 前先 `previous.destroy('replace')`，用 runtime key 防监听叠加（`:41`）。

**⑥ 行动选项桥**（把模型写的选项变成按钮，`行动选项桥.md:21-37`）：
正则先铺容器（`data-xyopt-root`）→ 桥扫**最新楼**的 root → 解析 `data-xyopt-raw` → 往 `data-xyopt-list` 填 `data-xyopt-choice` 按钮 →
点击：**默认换行填进输入框**（可多选再改），勾了「直发」就立刻发送并触发生成。
边界：旧楼由「旧楼选项隐藏」正则清空、**桥不服务历史楼**；直发/折叠偏好存 `localStorage`；
**桥不写变量**（选项只影响输入框和生成触发）；**不要在控制中心再做一套平行选项解析**。

**⑦ ★ 静默失败（与我们同族，务必写进规程）**：壳与真身不在同一 window，宿主全局（`$`/`Mvu`/`eventOn`）**不会自动进 blob iframe**；
桥没补上 ⇒ `readCurrentHudVariables` **静默返回空、界面全是 `--`**（`控制中心与状态栏.md:46`）。
同页反例更值钱：「**仿真壳不复现『壳→blob→真身』三层链 ⇒ 仿真绿、真机红**」（`:53`）——
与艾瑟兰第 326 轮「面板画得出 ≠ 桥在」是同一个坑。

**⑧ DOM 协议**：界面用 `data-*` 属性 + 属性选择器当契约；根上 `container-type: inline-size`，**窄了自动单列**（`行动选项桥.md:49`）。

**⑨ 「三写」原则**（写规则时同时写三处）：变量、资料库动态条目、玩家行动消息；
**桥是白名单**，不是把整个 `stat_data` 暴露给 HUD 乱写（`小手机与宿主桥.md:56`）。

**⑩ 边界**：**不要把大 HTML / 小手机塞进 `first_mes`**（`:60`、`控制中心与状态栏.md:57`）·
控制中心入口用**脚本按钮 API（魔棒下级菜单）**，**不在输入框上方插 DOM**；切聊天会拆掉顶栏 ⇒ 订 `CHAT_CHANGED`，延时约 250ms 再 `ensureWandEntry()`（`:34`）。

**⑪ 通用 vs 宿主相关**（这一栏决定哪些能写给「任意卡」）：
**通用**＝入口与内容分层 · 单例 vs 每份要去重 · 向上爬找宿主窗 · runtime 键 + 先 destroy 再挂 · 桥是白名单最小面 ·
大 HTML 不进首条消息 · `data-*` 当协议 · 旧楼不服务 · **三层链要按真机验**。
**宿主相关（换成 ElecKoi 就不能照抄）**＝Tavern Helper 的 `getVariables`/`Mvu`/`eventOn` · `#extensionsMenu`/魔棒菜单 · `CHAT_CHANGED` · git-mount/blob + `injectBridge`。
⇒ ElecKoi 侧的对应物我们已经有：`<!-- eleckoi:rich-replacement:start/end -->` 标记（313）· `order:22` 标记中和（322）·
`<meta name="eleckoi-author-api">`（326）· 变量 schema 必填（328–330）—— 同一族「**静默失败**」，已收进规程 §九 五条契约坑。

### 6.6 插件 / 扩展 / 资源分发（`sillytavern-extension-dev` 一路已回）

**A · 扩展最小做法**（ST UI 扩展＝`manifest.json` ＋ 浏览器入口模块；卡内 TH 脚本、STScript/API 签名、服务端插件各走别的路）

- **未获授权不得安装/更新/重载/启用**；动手前先读：manifest、包/模块设置、入口、样式、locales、构建脚本、测试。
- **保持稳定契约**：扩展 ID、设置命名空间、公开钩子、存储键、导入格式。
- `activate` **只做同步加载期设置**；此后每一个监听 / 定时器 / prompt 注入 / 宏 / 函数工具 / DOM 挂载 / 媒体句柄都必须**确定性清理**。
- 优先 `SillyTavern.getContext()`；设置与 DOM ID 用稳定扩展 ID 命名空间。
- ★ **能力快照 ≠ 通用 API 保证**：`check-extension-capabilities.mjs --contract … --snapshot installed-snapshot.json` 只证明**某一个已装环境**。
  弃用字段＝warning · 路径逃逸/缺入口＝error · 缺必需能力＝**blocker**。
- 脚手架先 dry-run（`--spec … --out staging`）→ 核对输出根与文件清单 → 才 `--write`。
- ★ **静态门证明不了**：安装、重载行为、真实事件载荷、设置持久化、UI 渲染、卸载清理 —— **全部记为 live gate**。

**B · 资源分发与加载**

- **Source-first**：改源再 compose，**不手改导出 JSON/PNG**。主链＝`profile/recipe → 校验 → compose → pack(JSON，可选 PNG) → 世界书版本绑定 → 嵌入载荷对账`；
  **出卡之后不要再往 JSON 补「最后一刀」**。
- `registry.json` 是**机器真源**；recipe 只选模块＋声明 `requiredOutputs`，**不存第二份构建逻辑**；替换公共组件双向登记 `replaces`/`replacedBy`。
- CDN 挂载一律锁版本（`cdn.jsdelivr.net/...@<version>` 永久缓存；不带版本约 7 天）；双源 fallback ＋ 离线 vendor。
- 远程加载写成状态机 `idle/loading/loaded/error`，**契约未就绪 fail closed**。
- 回封易漏：交错 `insertion_order`/`display_index`/`cfSortKey` 一次写齐；**两套清单别混**（产品线族表 vs 组件库 registry+recipe）。
