# ElecKoi 制卡工具 · 使用说明

> 名字：**forge**。它管一件事——**把「写卡」从手搓嵌套 JSON，变成改一份人读得懂的 YAML。**
>
> 设计约定只有一条：**`spec.yaml` 是唯一真相，`card.json` 是派生物。只手改 spec，别手改卡。**

---

## 一、它是什么，为什么需要它

ElecKoi 的卡（`eleckoi.character-card`）把「设定库」和「变量」各自压成了一坨 **JSON 字符串**，
正则单独一层。手改的代价是：少一个花括号、顺序错一位，**软件不报错，只是静默读不到**。

forge 做四件事：

| 做什么 | 怎么做 |
|---|---|
| **拆** | 卡 ⇄ 人可读的 YAML（唯一真相） |
| **拦** | 打包前就挑出「会被平台静默失效」的字段（见 §五，这是本工具独有的一段） |
| **通** | 酒馆（SillyTavern）卡 / 世界书 → ElecKoi 卡，存量内容不必重写 |
| **加** | 往卡里**从无到有**加条目 / 分组 / 变量 / 正则；变量一次写全三处，删了进回收站 |

## 三、二十八个命令

> 忘了参数不用翻这份表：**在命令后面加 `--help`** 就行，例 `python forge.py entry --help`。

```
python forge.py make   <卡稿.yaml> [--到 <目录>] [--试] [--覆盖]   **一次落成**整张卡（--模板 出骨架；--试 只验证不出）
python forge.py new    <你的卡名> [--模块 骰子,备份]  开一张新卡（内容层 + 界面层一起生成）
python forge.py new    <卡名> --从 <卡.json / 包.zip / spec.yaml / 工程目录>   接手现成的卡：界面层照抄骨架，内容层用它（卡名用你给的新名）
python forge.py name   <工程 或 spec> --看 | --改 <新卡名>   看 / 改卡名（spec 与界面配置两处一起改）
python forge.py mods   [--工程 <工程>]         列出模块（带版本；给工程则标出接没接）
python forge.py add    <模块> <spec.yaml>      给已有卡接一块现成机制（内容 + 界面一起接）
python forge.py drop   <模块> <spec.yaml>      撤掉（按账本精确撤，接之前的样子还在）
python forge.py entry  <spec> --新 "标题" [--模板 常驻|必读|关键词|选读|开场] [--分组 X] [--正文 …] [--关键词 判定,掷骰]
python forge.py entry  <spec> --列 | --看 <id或标题> | --复制 <id或标题> [<id或标题>…] [--到 分组] | --改 <id或标题> [<id或标题>…] [字段开关] | --挪 <id或标题> [<id或标题>…] [--到 分组] | --删 <id或标题> [<id或标题>…] | --启用|--停用 <id或标题> [<id或标题>…]
     （--改 / --复制 / --挪 / --删 / --启用 / --停用 后面给一串就是**批量**：一次落盘、一条回收记录；
       --改 一串＝这批条目同时改成同一组字段，值域只要有一条会被降级就整批不落盘；
       --复制 一串＝一次复制几条，副本顺在各自原件后面，--到 分组 能让副本落进那个组）
python forge.py opener <工程 或 spec> --看 | --正文@开场白.txt [--不写回] | --补齐 | --写回   开场白（有界面层时真源在 hud.conf.json；只有 source/ 时真源就是 spec 里那条）
python forge.py group  <spec> --列 | --新 <名> | --改名 <旧> --叫 <新> | --删 <名>
python forge.py var    <spec> --列 | --新对象 <名> [--父 对象] | --新 <对象>.<变量> [--类型 number] [--初值 1] | --改名 <id或对象.变量> --成 <新名> | --改名对象 <对象> --成 <新名> | --换对象 <id或对象.变量> --到 <对象> | --删 <id或对象.变量> [<id或对象.变量>…] | --删对象 <名> | --对齐
     （--删 后面给一串就是**批量删**：每个变量三处一起撤，一次落盘、一条回收记录）
python forge.py regex  <spec> --列 | --新 "说明" --模式 '…' --替换 '…' | --删 <id> | --启 <id> / --停 <id>
python forge.py trash  <工程 或 spec>         看回收站里有什么（--还原 1 放回最近一条，--清空）
python forge.py theme                          看有哪些皮肤
python forge.py theme  <名> <工程>              换皮肤（只覆盖颜色槽，不碰版式）
python forge.py theme  --巡览 <工程>            五套皮肤摆一起对比（不改工程现在的皮肤）
python forge.py theme  --撤 <工程>              回到核心默认
python forge.py theme  --导出 <工程>            把这张卡调好的配色导成一份皮肤文件（可发人）
python forge.py theme  --导入 <皮肤.json> <工程>  套上别人给的皮肤（加 --装 则收进主题库）
python forge.py hud    <工程 或 spec> [--写回]  组装卡内 HUD（出 预览.html）
python forge.py unpack <卡.json> [-o 出.yaml]  卡 -> 可读 spec.yaml
python forge.py build  <spec.yaml> [出.json]   spec -> 卡
python forge.py check  <文件 或 目录>           校验（值域 + 一致性 + 护栏 + 界面守则 + 工程自洽，可批量）
python forge.py bundle <工程> [-o 出.zip]       把整个工程打成一个包（分发 / 备份）
python forge.py import <包.zip 或 卡.json> [--到 目录] [--改名]   收包：落到本地成一张工程
python forge.py analyze <卡文件> ...            拆解报告（酒馆 / ElecKoi 都认）
python forge.py to-eleckoi <酒馆卡> <出.yaml>   酒馆卡 -> ElecKoi 规格
python forge.py to-tavern  <ElecKoi卡> <出.json> ElecKoi 卡 -> 酒馆 V2 卡
python forge.py png    <卡.json 或 spec.yaml> [-o 出.png] [--图 封面.png]
                                              出**能当图片导入**的卡（tEXt eleckoi-card）
python forge.py preset <卡.json 或 spec.yaml> [-o 出.preset.json] [--png [出.png]]
                                              出一份 ElecKoi **创作预设**（分类选「创作预设」）
python forge.py manual <spec 或 卡> [-o 出.html] 出人读手册（同时出索引）
python forge.py index  <spec 或 卡> [-o 出.md]   出给 AI 的导航索引
python forge.py coach  [--到 <目录>]            出「怎么做一张卡」：给 AI 的规程 + 给 ElecKoi 的向导卡
python forge.py diff   <a.json> <b.json>       语义比对（忽略键序与空白）
python forge.py domains                        打印真值域表
python forge.py guide   [--节 <名>|--篇 <名>|--对话 <名>|--全文]  打印制卡规程（给 AI 按需取：不给参数＝目录）
python forge.py selftest                       自检：四十二项，含负向用例与往返比对
```

> **在任何命令后面加 `--沙箱`**（或先 `export FORGE_SANDBOX=1`）＝ 沙箱友好模式：
> 只创建、只覆盖，**不删文件、不改名** —— 给「ElecKoi 里的 AI 直接跑 forge.py」那种
> 受限环境用的。代价是丢掉原子落盘，能不用就不用。

> **`--复制` / `--挪` / `--删` / `--启用` / `--停用` 后面可以跟一串**（`--挪 甲一 甲二 甲三 --到 世界`、`--复制 甲一 甲二 --到 世界`）。
> 一次落盘、**一条**回收记录（`trash --还原 N` 一次全捞回来）；有认不出的名字就**整批停下**、
> 一条不动 —— 「挪了 10 条其实进了 6 条」是最难收拾的状态。
>
> **改变量名 / 变量对象名用 `var --改名`**，别手改也别删了重建。名字同时是面板上那一行、
> 初值里那一格的**键**、Zod 里那个**字段名**；`--改名` 把三处一次挪过去，id 不动
> （卡里按 id 引用的地方不会断）。正文里写着旧名字的地方**只报不改** —— 工具分不清
> 那是变量名还是恰好同字的常用词。

> **要写一段话的地方，值都可以写成 `@文件名`**（`--正文` / `--标题` / `--说明` / `--模式` / `--替换`…）。
> 正文动辄几百字还带换行，塞进命令行要跟 shell 的转义规则搏斗，各平台还各不相同；
> 写成文件再 `@` 引就没这回事 —— 多长、多少换行、带不带引号都一样。
> 文件末尾那一个换行按编辑器习惯忽略。**文件名写错会当场报错**，绝不会把那串
> `@名字` 当正文写进卡里。例：`python forge.py entry <spec> --改 "核心 · 世界总纲" --正文@世界总纲.txt`

> **读一条条目现在写了什么**：`python forge.py entry <spec> --看 "id 或 标题"` ——
> 打它的全貌：正文全文（原样，多行不糊）、关键词、读取提示、触发方式、插入位置……
> 改之前先看一眼它写的是什么、靠什么触发。它是纯读，不落盘。

> 在 Git Bash / MSYS 里加正则注意：以 `/` 开头的参数（比如 `--模式 '/〔重点〕/g'`）会被 shell
> 当成路径展开成交互式 Windows 路径。先 `export MSYS_NO_PATHCONV=1`，或者把正则写进文件用 `@文件` 引。工具认得出这种被改写的值，会拦下来而不是照写。

### 开一张新卡

```
python forge.py new 我的世界
```

得到的是一个**分两层的工程**：

```
我的世界/
  source/我的世界.spec.yaml     内容层 ← 改世界观、条目、变量、正则，改这里
  模块账本.json                 接过哪些机制、并进来了什么 ← 撤模块靠它，别手改
  hud/                          界面层 ← 改建卡器 / 面板 / 悬浮球长什么样，改这里
    hud.conf.json               卡名、id 前缀、HUD 全局名、要接几条正则、现在用哪套皮肤
    hud.core.js                 通用核心：把变量树画成面板 + 建卡器 + 常驻悬浮球
    hud.css                     版式（**一个颜色都不写死**，全从一组 --hud-* 槽取）
    主题.css                    皮肤（只有颜色槽覆盖；由 forge theme 写，可没有）
    view_create.html            建卡器那一块的骨架
    view_card.html              面板那一块的骨架
    模块/<名>/<名>.js|.css      按需挂上的模块（借来的机制，撤掉就删目录）
  测试/test_core.js             界面纯函数单测（`node 测试/test_core.js` 跑）
  成品/                          ← build 的输出落这儿
  预览.html                      ← `forge hud` 产出：界面在浏览器里的样子
  皮肤巡览.html                  ← `forge theme --巡览` 产出：五套皮肤的对照图
  怎么开工.md                    ← 这个工程自己的小抄
```

`hud.core.js` **不含任何世界观内容**：你往 `variables` 里加一栏，面板上就多一行，不用改代码。

骨架里也没有世界观，只有**形状**：一条开场白、一条常驻、两条按需（一条资料、一条规则）。
一生成就是通的，而且**界面已经组装好、正则已经写回 spec** —— `selftest` 把这条钉成断言。

### 改界面：`forge hud`

```
python forge.py hud 我的世界            # 组装 + 出预览页 + 校验（不改 spec）
python forge.py hud 我的世界 --写回      # 组装无问题后，把正则与开场白写回 spec
                                         # （改开场白正文别手改 JSON，用 opener，见「三、命令」）
```

界面这一段代码是**整段注进宿主页面**的，所以它跟宿主共用一个 DOM。收尾这一步做三件事：

1. 把 `hud/` 下的 CSS / JS / 视图拼成**完整 HTML 文档**（ElecKoi 只把完整文档提升成富文本消息，
   片段会被当普通文本吐出来），顺手把 conf「模块」里那几个模块的脚本与样式拼在核心之后；
2. 转成正则的替换串（`$` 要转义成 `$$`），按 conf 里的 order 写回 `source/*.spec.yaml`；
3. 出一份浏览器可直接打开的 `预览.html`（里面用假数据 + ElecKoi 桩，四个视图都能点）。

拼装的顺序是 **核心 → 皮肤 → 模块**：皮肤压核心（换色），模块压皮肤（某个模块自带的强调色，比如骰子按结果分色，该赢）。

**改了 `hud/` 就要重跑一次 `hud --写回`**，否则卡里的正则还指着旧的那一版页面。


### 改一张别人的卡

先弄清手里是哪种东西，再选路 —— **别猜**：

| 拿到的是 | 用什么 | 拿到的是什么 |
|---|---|---|
| 单张 `.card.json` | `analyze` 先看 → `unpack` / `import` | 只有**内容层**（界面层 `hud/` 本来就不在卡里，不算丢东西） |
| 工程包（`.zip`） | `import` | **整张工程连界面层**，跟 `new` 建的一模一样 |
| 酒馆卡 | `analyze` → `to-eleckoi` | 一份 spec 草稿（见下一节，转出来还要人工确认三处） |

```
python forge.py analyze 别人给的.card.json     # 它是什么卡、几条条目、多少字（只读不落盘）
python forge.py import  别人给的.card.json --到 .   # 收成本地工程，接着用 entry --改
python forge.py import  别人的工程.zip      --到 .   # 工程包会连界面层一起收下来
# 改完
python forge.py check  别人给的 && python forge.py build 别人给的/source/别人给的.spec.yaml
```

单张卡收下来只有 `source/` 一层 —— 想要界面，用 `new` 开一张新卡把条目搬过去，
或给新卡接界面再 `hud --写回`。

`unpack` 不丢东西：认不得的字段一律原样保留（放进 `#其它顶层字段(原样保留)`）。

### 从酒馆搬内容

```
python forge.py analyze   我的酒馆卡.png        # 先看它有什么
python forge.py to-eleckoi 我的酒馆卡.png out.spec.yaml
python forge.py check     out.spec.yaml
```

`analyze` 认四种输入：`*.json`（V1/V2/V3 卡、独立世界书）、`*.png`（数据藏在 `chara`/`ccv3` 元数据块）、
`*.charx`（是 zip，里面有 card.json）、`*.webp`。

> **不猜。** 认不出的结构直接报错，不做「尽力解析」——猜错比报错贵得多。

### 把 ElecKoi 卡搬去酒馆（反向）

```
python forge.py to-tavern 我的卡/source/我的卡.spec.yaml 出.json
```

映射规约（决定了「换过去还能不能用」）：

| ElecKoi | 酒馆 |
|---|---|
| 常驻 + `insert_role: system` | 并进 `data.description`（酒馆里只有这几格是真的每轮都进） |
| 常驻 + 其他 role | `character_book` 条目，`constant=true` |
| 按需 + 有关键词 | `character_book` 条目，`keys=关键词` |
| 按需 + 无关键词 | `character_book` 条目，`keys=[]`（**⚠ 酒馆不会自动触发它**） |
| 开场白 | `first_mes` + `alternate_greetings` |
| 变量 / 分组 / 未映射字段 | `data.extensions.eleckoi`（原样存着，回迁时取回） |

最后一行是重点：**回迁是无损的**。`to-eleckoi` 认得出 `extensions.eleckoi`，会走「回迁」模式
把变量、分组、正则、条目 id 与顺序全部取回来，条目正文以酒馆侧的当前内容为准
（你在酒馆里改过的会被带上）。已验：艾瑟兰 2.5MB 实卡转一圈回来，**语义完全一致**。

工具会**点数**那些「按需但没写关键词」的条目并说清根因：ElecKoi 有「由 AI 自己选读」
这一档（`agent_tool` + `normal`），酒馆没有对应能力。这是真实的能力缺口，不是转换漏了。

### 出两份文档

```
python forge.py manual 我的卡/source/我的卡.spec.yaml     # 出 .手册.html + .索引.md
```

- **手册**（给人看）：单文件 HTML，带目录、分组树、条目清单、可折叠的条目全文、
  变量表、正则表、真值域表、体检结果。拿给别人看这张卡有什么，他不用装任何东西。
- **索引**（给 AI 看）：Markdown 清单 + 一张「想改什么、动哪里」的对照表。
  下次让 AI 改这张卡，先喂它这一份，比喂 3000 行 spec 高效得多。

两份都从同一份 spec 生成，所以永远不会与卡脱节。

### 让 AI 替你开新卡：`forge coach`

上面讲的都是**你自己动手**。你要是想把「开新卡」这件事交给 AI，缺的不是命令，
是**一份 AI 读得懂的制卡规程** —— 它得知道一张卡由什么构成、条目怎么配触发、
怎么把角色写活、哪些写法会被平台静默吃掉。这一份就是 `coach` 出的：

```
python forge.py coach              # 出到 ./向导/
python forge.py coach --到 D:\临时\向导
```

一份内容，两个出口：

| 产出 | 给谁 | 怎么用 |
|---|---|---|
| `向导/AI制卡规程.md` | **电脑上的 AI**（Claude Code / WorkBuddy / Codex） | 丢给它，说「照这个给我做一张卡」 |
| `向导/SKILL.md` | 同上（带 frontmatter） | **门牌版**（工具在哪 + 规矩 + 指向规程）：整个目录拷进 `~/.workbuddy/skills/`，以后一句话唤起；规程更新后不用重装 |
| `向导/制卡助手/成品/制卡助手.card.json` | **ElecKoi 里的 AI** | 导入 ElecKoi 挂上：它变成制卡师，在对话里访谈你，一层层交条目内容 |

两份出口共用同一套**方法论九篇**：机制（卡由什么构成）/ 条目触发怎么选 / 预算（每句话都在跟聊天记录抢位置）
/ 世界 / 故事 / 角色 / 写法（怎么把角色写活）/ 变量 / 界面；外加一章**红线**（被静默吃掉的写法）。

**规程不必一次读完**：`python forge.py guide` 出目录，再按需取一段 ——

```
python forge.py guide                 # 目录：有哪些节 / 哪些篇 / 哪几篇必读 / 哪几段「对话」
python forge.py guide --节 三          # 一节（一 开工流程 / 三 开场白 / 六 验收标准 / 九 红线 …）
python forge.py guide --篇 预算        # 一篇方法论（预算 / 写法 / 角色 / 世界 / 变量 …）
python forge.py guide --对话 访谈      # 一段「在对话里做卡」（总则 / 访谈 / 交付 / 红线）
```

名字认不出会当场报错并列出全部候选；撞名的（两篇同前缀）报「不止一个」让你写全，绝不静默挑一个。
装了「制卡工坊」插件的 AI 在 ElecKoi 里就是靠这条自己把知识取到手的
（`["guide","--篇","写法"]`），不必等人把规程贴进对话。

向导卡自己就是范例：由 `coach` 生成，体检 0 错、常驻字数守在它自己主张的预算内。

### 一次落成：`forge make`

`new` → `group` → `entry` × N → `var` → `regex` → `opener` → `build` → `check` 是七八次进程启动。
人用不累，**AI 在对话里用就贵**：每次调用都是一整轮（上下文从头重发一遍）。
内容想清楚之后，把这张卡写成一份**卡稿**，一趟落成：

```
python forge.py make --模板            先打出一份骨架（存成文件照着填）
python forge.py make 我的卡.yaml       一趟：建工程 + 写条目 + 加变量正则 + 换开场白 + 出成品 + 体检
python forge.py make 我的卡.yaml --试   只验证不出（稿子改了先试一遍）
python forge.py make 我的卡.yaml --覆盖 那份工程已经在了，照稿子重落一遍
```

稿子写的是**这张卡该长什么样**，不是「先做这步再做那步」：

- **条目按标题认人** —— 卡里已有同名的就改它，没有才新建；不必先搞清楚骨架里现成有什么。
  想清掉骨架自带、而稿子里没提到的条目，写一行 `清空条目: true`；想删某一条，写 `删: true`。
- **分组 / 变量对象缺了自动补**，报告里单列一份（名字打错才看得见）。
- **全程在临时目录里做，全绿了才整棵拷到目标位置。**
  稿子有毛病时**目标位置一个字都不会被写**；静态能查的（模板名 / 类型 / 值域会不会被静默降级）
  **一次报全**，不用改一处跑一次。
- 目标已有一份工程时默认停下 —— `--覆盖` 才允许重落，而且**只认同一张卡**
  （目标里有 `source/<卡名>.spec.yaml` 才算），别人的东西一律不碰。

它也是**沙箱友好**的（全程只创建、只覆盖）：在 ElecKoi 里直接跑命令的 AI 加 `--沙箱` 照样一趟落成。

### 挂模块：给卡接一块现成机制

```
python forge.py mods                               # 看有哪些、各是什么版本
python forge.py add  骰子 我的卡/source/我的卡.spec.yaml
python forge.py drop 骰子 我的卡/source/我的卡.spec.yaml   # 后悔了就撤
python forge.py new 我的世界 --模块 骰子,备份        # 开卡时顺手接
python forge.py mods --工程 我的世界                 # 这张卡接了什么、要不要更新
```

自带五个模块：**骰子**（判定规则 + 7 条渲染正则）、**尺度**（叙事尺度三档）、
**备份**（档案过夜）、**点数池**（属性预算）、**代笔**（AI 帮填栏位）。每个模块带一个版本号。

每个模块给的是「条目 / 正则」（**内容**）和/或「脚本 / 样式」（**界面**）。两类东西，两个去处：

| 模块给的 | 落到哪 | 之后 |
|---|---|---|
| 条目 · 正则 | `source/<卡>.spec.yaml` | **并一次就归这张卡**，此后改就改 spec |
| 脚本 · 样式 | `<工程>/hud/模块/<名>/<名>.js|css` | 每次 `forge hud` 时重新拼；撤掉就删目录 |

条目两种并法：

| 写法 | 效果 |
|---|---|
| `替换: <参照条目>` | 顶掉那一条，没写的字段沿用被替那一条（骰子就走这条，顶掉骨架的「规则 · 判定」） |
| `底稿: <参照条目>` | 照那一条的形状克隆一条新的，加到末尾（备份 / 点数池等走这条） |

参照条目只写 id 后半截即可（`rule-check` 能匹配 `card89ef71-entry-rule-check`），
所以模块不必知道每张卡的前缀。**重复接同一个模块会自动跳过**；
`id` / `order` / `tree_view_order` 这些「目录顺序」字段由本工具接管，模块里写了也忽略。

脚本/样式里的 `skel` / `SKEL_HUD` 在落盘时会被换成这张卡的 —— 所以**模块跨卡通用，一个字都不用改**。

> **接完模块记得再跑一次 `hud --写回`**：条目与正则当场就进 spec 了，但脚本/样式得等组装
> 才会拼进页面。（`new --模块 a,b` 是连着做完的，不用手动补。）

#### 撤模块：`forge drop`

模块是**覆盖**进 spec 的 —— 不存原样就再也回不去。所以每接一个，工具都往工程里的
`模块账本.json` 记一笔：并了哪几条、**替换的那条原来长什么样（整份存着）**、要删哪些正则与界面文件。

```
$ python forge.py drop 备份 我的卡/source/我的卡.spec.yaml
  · 撤 备份（版本 1.0.0 · 接于 2026-10-08T14:54:15）
      ✓ 删掉「规则 · 档案备份」
      ✓ 从 hud.conf.json 的「模块」里摘掉
      ✓ 删掉 hud/模块/备份/
```

四件事，一样不少：替换的**还原**、新增的**删掉**、正则**按 id 删**、界面文件与登记**一并摘掉**。

两条边界：

- **只撤账本里记着的。** 你自己手写进 spec 的东西，工具分不清那是谁的 —— 宁可不撤，也不替人删。
- **接完又改过的会先警告。** 撤的时候会拿条目的指纹跟「并进来的那一刻」比；不一样就提示
  「这条接模块之后你又改过，还原会把那处改动一起盖掉」，然后照撤（账本记着它归模块）。

`forge mods --工程 <工程>` 会标出每个模块的状态：`●` 已接 · `○` 未接 · `▲` 仓库里的比你卡上那份新。
**卡上的条目归卡**，所以模块升级不会自动覆盖你的卡 —— 想吃新版就 `drop` 再 `add`。

## 三·五、换皮肤：`forge theme`

```
python forge.py theme                           # 看有哪些皮肤（带对比度）
python forge.py theme 墨夜 我的卡/               # 换
python forge.py theme --巡览 我的卡/              # 五套摆一起对比（不改工程现在的皮肤）
python forge.py theme --导出 我的卡/                # 把这张卡现在这份配色导成文件（可发人）
python forge.py theme --导入 别人的皮肤.json 我的卡/  # 套上别人的皮肤
python forge.py theme --装  别人的皮肤.json 我的卡/  # 套上，并且收进 assets/主题/ 留着自己用
python forge.py theme 我的卡/                     # 看这张卡现在用哪套
python forge.py theme --撤 我的卡/                # 回到核心默认
```

自带五套：**羊皮卷**（默认）· **墨夜**（深底浅字）· **霜白**（冷白青灰）· **朱砂**（朱红描金，方角）· **苔原**（苔绿米黄，圆角）。

### 为什么颜色和版式分两份文件

`hud.css` 里**一个色值都不硬编码**，全部从一组 `--hud-*` 槽里取（正文 / 次级 / 淡字 / 四种底色 /
两层线 / 两块淡底 / 强调 / 警示 / 阴影 / 圆角 / 字体）。主题只写这组槽：

```css
/* hud/主题.css —— forge theme 写的，就这么点东西 */
.hud,
.hud-ball,
.hud-ballpanel {
  --hud-ink: #e6dccb;
  --hud-paper: rgba(30, 28, 24, 0.78);
  /* … 共 18 个槽 */
}
```

分成两份之后：换皮肤**不可能**弄坏版式；核心升级**不会**覆盖你的配色；
同一份主题**跨卡通用**（换卡只换 `hud.conf.json`，主题一个字不用改）。

想自己调：直接改 `hud/主题.css`（下次 `forge theme` 会覆盖它）；
要长期留住，照着 `assets/主题/<名>.json` 的形状做一个新主题 —— 只写想改的槽，
没写的落核心默认。**写错的槽会当场报错**：那种错不报错、只是永远不生效，谁也不会发现。

### 对比度体检

皮肤最容易出的问题不是「难看」，是「**看不清**」：浅灰字配浅底，在编辑器里预览时刚好能看见，
压到真界面上就成了灰糊糊一片 —— 没人会报这个错，只会让人觉得「这张卡怎么这么累眼睛」。

卡的底是**半透明**的（要压在宿主的消息背景上），宿主什么颜色我们不知道，所以按
「宿主纯白」和「宿主近黑」各算一遍，**取更差的那个**：

```
  羊皮卷   18 个槽 · 对比度 正文 10.9 · 次级 4.7 · 淡字 2.2
  霜白     18 个槽 · 对比度 正文 11.0 · 次级 4.5 · 淡字 2.7
```

底线：正文 ≥ 4.5（WCAG AA）· 次级 ≥ 3.0 · 淡字 ≥ 2.0。低于底线会在换皮肤时直接提示。

## 四、一张卡由什么构成

```
角色壳（名字 + 挂载关系）
  └─ 设定库：装所有内容（世界、故事、角色、规则）
       ├─ 两类固定条目不可删：AI角色开场白、角色扮演任务计划
       └─ 条目 × N（每条有标题、正文、触发方式、读取策略、「什么时候读我」）
  └─ 变量（可选）：要记住会变化的状态时才加
  └─ 正则（可选）：只管显示格式，不承担内容
  └─ 图片（可选）：圆形头像 / 方形头像 / 3:4 立绘，三个独立槽位
```

**三条纪律**（来自实机踩坑）：

1. **常驻只放每轮必须看见的东西。** 身份、准则、输出约定。其余一律走按需。
2. **一条条目只干一件事。** 越长越该拆——拆开之后各自有自己的标题和「什么时候读我」。
3. **资料类走按需，规则类走关键词。** 资料一直在目录里、要读才读、零 token；规则不该等被问到才生效。

## 五、护城河：真值域表

**市面上所有酒馆制卡工具都不知道 ElecKoi 的真实字段值域。** 于是导进去的卡，
有一半字段是「看着对、其实没生效」——因为平台的策略是**静默降级**，不报错。

这张表来自反编译本机 ElecKoi 0.2.8（`app.asar` 逐字节全包搜索），`forge check` 会照它拦：

| 字段 | 合法值 | 缺省 | 旧值会怎样 |
|---|---|---|---|
| `trigger_mode` | `always` / `agent_tool` | `always` | — |
| `agent_read_strategy` | `required` / `keyword` / `normal` | `normal` | **`variable_condition` → 静默降级为 `normal`** |
| `kind` | `normal` / `opening` / `history_compaction` / `hidden_tool_timeline` | `normal` | — |
| `dynamic_mode` | `standard` / `ejs_reference` | `standard` | `ejs_controller`、`single_condition` → `standard` |
| `content_mode` | `plain_text` / `ejs` | `plain_text` | — |
| `keyword_condition` | `none` / `any` / `all` / `not_any` | `none` | 空串按 `none` 处理 |

另有一个字段平台**根本不读**：`agent_read_condition`（全 asar 出现 0 次）。
留在卡里只是死重量，且会让后来人以为「变量条件加载」是生效的——其实不是。

随时可以打印全表：`python forge.py domains`。

### check 还会挑出什么

| 代号 | 拦的是什么 |
|---|---|
| `DOMAIN-LEGACY` / `DOMAIN-UNKNOWN` | 字段值会被平台静默降级 |
| `CONST-NO-POSITION` | **常驻条目没给插入位置** → 会被直接过滤掉，一个字都进不去 |
| `KEYWORD-EMPTY` | 策略是「关键词命中」但没写关键词 → 永远读不到 |
| `HINT-MISSING` | 按需条目没写「什么时候读我」 → AI 不知道何时该读 |
| `OPENING-*` | 开场白条目缺方案 / 默认指向不存在的方案 |
| `GROUP-MISSING` / `VAR-ORPHAN` | 引用完整性：分组、变量对象、父对象 |
| `VAR-SYNC-*` | **变量三处不同步**（见下） |
| `RE-SLASH` / `RE-ORDER` | 正则收尾不完整、order 撞车（替换是「谁先认走就是谁的」） |
| `SIZE-CONST` / `SIZE-ENTRY` | 字数护栏：常驻合计、单条长度 |
| `HUD-*` | **界面层越界**（见下），只在这份卡住在带 `hud/` 的工程里时查 |
| `PROJ-*` | **工程层两处对不上**（见下）：模块目录↔conf、账本↔现状、spec↔成品 |

### 变量三处不同步（`VAR-SYNC-*`）

一个变量要同时写在**三处**，少任何一处都不会报错，只会安静地少一块：

| 处 | 少了会怎样 |
|---|---|
| `variables.objects` | 面板是按这张表画的 —— 表里没有，界面上就不出现那一格 |
| `variables.initial_state` | 宿主初始化时没有它，界面读不到 |
| `variables.schema_code`（Zod） | **写入被静默丢掉** —— 这是最难查的一种 |

这是「档案备份」模块踩出来的那口坑（对象 `存档` ＋ 变量 `角色`，四处要同时在），
`check` 把它变成了机器检查：任何一处分叉都报出来。

### 界面层的边界守则（`HUD-*`）

界面那段代码是整段注进宿主页面的，跟宿主共用一个 DOM —— 越界一处，宿主的界面就跟着变形。
`check` 会逐文件扫 `hud/`：

| 代号 | 拦的是什么 |
|---|---|
| `HUD-CSS-PREFIX` | CSS 里有选择器**没带 `.hud` 前缀** —— 漏一个裸选择器（`body` / `.message`）就把宿主染了 |
| `HUD-FORBID` | 三反引号（宿主当富文本，会截断）/ `<!--` / `</script` 字面量 / 模块里的 `position:fixed` |
| `HUD-MOD-MISSING` | conf 的「模块」里写着的目录不存在 —— 比不接更坏：看着是接了的，界面却安静地少一块 |
| `HUD-CONF` | `hud.conf.json` 读不出来 |

> 核心自带那颗常驻悬浮球（`.hud-ball`）本来就该脱离消息流，所以 `position:fixed` 这条
> **只对模块查**。宁可少报一条，也不误报 —— 误报会让人不再看报告。

### 工程层对不对得上（`PROJ-*`）

上面那些查的是「**这张卡**自己通不通」；这一组查的是「**这个工程**里各层对不对得上」。

麻烦在于，这几种错的共同点是 —— **一个都不报错**：

| 代号 | 什么时候出现 | 不查出来会怎样 |
|---|---|---|
| `PROJ-MOD-UNLISTED` | `hud/模块/<名>/` 目录在，`hud.conf.json` 的「模块」里没写它 | 组装**只按 conf 那一行拼** → 这个模块的脚本与样式一个字都不进页面，界面上安静地少一块 |
| `PROJ-MOD-NO-LEDGER` | conf 登记了，`模块账本.json` 里没有它 | `forge drop` 撤不掉（账本是唯一的依据），你以为撤了其实没撤 |
| `PROJ-LEDGER-GONE` | 账本记着替换/新增过的条目，spec 里已经没有 | 撤模块时那一处撤不动 |
| `PROJ-LEDGER-DRIFT` | 接了模块之后你又改了那条 | 撤模块会**连你那处改动一起还原**（账本存的是接之前那一份） |
| `PROJ-LEDGER-REGEX` / `PROJ-LEDGER-HUD` | 账本记的正则 / 界面文件不在了 | 撤的时候少撤几条，或删不干净 |
| `PROJ-HUD-UNWRITTEN` | conf 里那条正则不在 spec 的正则里 | **卡里就靠这条正则把界面注进去** —— 少它，导入 ElecKoi 之后界面根本不会出现 |
| `PROJ-HUD-PATTERN` | spec 里那条正则的模式和 conf 那份不一样 | 下次 `hud --写回` 会把它按 conf 覆盖掉 |
| `PROJ-STALE-CARD` | `成品/*.card.json` 比 `source/*.spec.yaml` 旧 | **交付给 ElecKoi 的永远是成品** —— 你改了 spec 没重出，导进去的还是老内容 |
| `PROJ-STALE-PREVIEW` | `预览.html` 比 `hud/` 下的文件旧 | 预览不是最新的（不影响卡本身） |
| `PROJ-NAME-DRIFT` | 界面配置里的「卡名」与 spec 的 `character.name` 不一样 | 导进 ElecKoi 显示的是 **spec 里那个名字**，会跟工程目录对不上；用 `forge.py name <工程> --改 <新名>` 一次改两处 |
| `PROJ-MULTI-SPEC` | `source/` 下有两份以上 spec | 去哪一层都靠「唯一那份」定位，两份就谁也不知道该用哪份 |

两条防误报的规矩：

- **`PROJ-HUD-UNWRITTEN` 只在「已经出过成品」的工程上查。** 骨架那类**模板源**本来就没有
  成品、也没有那几条正则（`new` 拷一份出来才会写回），拿它当错报就是误报。
- **有第二种合理解释的一律降成提示。**「账本与现状指纹不符」多半是你有意改的，
  它只提醒你「撤的时候会连这个一起撤」，不拦。

顺带一提：`forge hud` 组装时会**主动报一句**「这个目录没登记，不会被拼进去」——
把「安静地少一块」变成当场说一句。

### 批量校验

`check` 也吃目录，一次把工程里的 spec 与卡全过一遍：

```
python forge.py check 我的世界
python forge.py check 甲/乙/丙        # 一次看三个工程
```

真实效果（对艾瑟兰 174 条的实卡）：

```
条目 172 · 分组 6 · 变量 49 · 对象 8 · 正则 15
常驻    : 6 条 / 8773 字（护栏 3000 字）
  ! [SIZE-CONST] 常驻正文合计 8773 字，超过护栏 3000 字
      → 最大的是：核心 · 世界总纲(2050字)、常规 · 状态面板与输出约定(1805字)、核心 · 叙事尺度(1719字)
  · [ORDER-CLASH] 同组内 order=26 撞车：常规 · 战斗与伤势、核心 · 建卡协议
结论：0 个错误 · 1 个警告 · 2 条提示
```

> 报告设计上刻意**不刷屏**：几十条同类问题聚合成一条，只列最大的前几个。
> 噪声会让人不再看报告，那比不报还糟。

## 六、打包与收包：`forge bundle` / `forge import`

```
python forge.py bundle 我的世界                 # -> 我的世界/我的世界.工程包.zip
python forge.py bundle 我的世界 -o D:\分享.zip
```

打包前会**重新构建一遍**（spec → 卡 → 手册 → 索引），所以包里不会有过期的派生物；
界面组装不过就停，不拿半成品覆盖。包里最上面一层是「我的世界/」，解开即可用：

```
source/<卡>.spec.yaml    内容真相（改它）
模块账本.json            接过哪些机制（撤模块靠它）
hud/                     界面那一层（改它、拼它）
测试/test_core.js        界面纯函数单测
成品/<卡>.card.json      交付物（导入 ElecKoi 的就是它）
文档/<卡>.手册.html      人读手册 —— 不用装任何东西，双击就看
文档/<卡>.索引.md        给 AI 的导航索引
预览.html                界面在浏览器里的样子
皮肤巡览.html            五套皮肤的对照图
怎么开工.md              这包怎么用
```

拿到这个包的人**不用装 forge** 也能看卡、看界面；要接着改再装工具。

### 包里那份 `包信息.json`

它是包的信封，不是工程的内容（只写进 zip，不落在工程目录里）：

```json
{ "格式": "forge.工程包", "卡名": "我的世界", "工具": "forge 0.14.0",
  "生成时间": "…", "界面模块": ["尺度", "备份"], "皮肤": "",
  "文件数": 22, "清单": { "source/我的世界.spec.yaml": { "大小": 8123, "校验": "9f2c…" } } }
```

**为什么值得有它**：zip 传一手，少一个文件、坏一个字节，谁也看不出来 ——
一直到别人的卡上界面空了一块才发现。有了清单，收包时能逐条核。

### 收包：`forge import`

```
python forge.py import 我的世界.工程包.zip              # 收到当前目录
python forge.py import 我的世界.工程包.zip --到 D://我的卡
python forge.py import 别人的卡.card.json               # 单张卡也认
python forge.py import xx.zip --改名                    # 同名就自动叫「…-2」
```

收包会做三件事，顺序不能颠倒：

1. **逐条查路径**（安全边界，不是风格检查）。zip 里的条目名是**别人给的字符串** ——
   写着 `../../../Windows/…` 或 `C://…` 是完全合法的 zip。照它写出去，就是「解压一个包，
   往系统目录塞文件」。绝对路径、`..`、任何一段带冒号的，一律**整包拒收**。
2. **核清单**：逐条比字节数与 sha256。对不上会**如实列出来**（少文件 / 字节数不符 / 内容不符），
   但文件还是解出来 —— 能看能改，只是别直接拿去出卡，先跟发卡的人对一下。
3. **自动体检**一遍，把「条目 / 分组 / 变量 / 正则」和「几错几警告」报出来。

同名工程已经在了会**停下**（不覆盖别人的东西）；要自动错开就加 `--改名`。

## 八、它和艾瑟兰 / 角色卡工作台的关系

艾瑟兰那边的 `card_kit.py` / `build_hud.py` 与本工具同源不同代：
