## 为什么要测

到现在为止，工具的所有验证都在**机器内部**完成：自检、校验、往返比对、盲跑。
这些都只能保证「**文件是对的**」，保证不了「**装进真客户端里好用**」。

真机上可能翻车的三件事，只有导进去才知道：

1. **导不进去**（0.2.8 换了架构，导入格式可能变了）
2. **导进去是半张卡**（条目在、变量丢；或者界面层不出）
3. **能导入但不生效**（条目读不进去、开场白不显示）

两张都要测。甲过关只证明内容层没事，乙才是工具的重头戏。

> 名词按规程：「纯内容卡」这个说法不准确 —— 一张卡从来不是「只有内容」：
> **角色壳**（名字 + 挂载关系）任何卡必有，**设定库**是主体，
> **变量 / 正则 / 界面 / 图片**四个都是可选项。甲卡 = 壳 + 库，其余不做，不是残卡。

## 甲：内容卡（约 3 分钟）

- [ ] 1. 打开 ElecKoi（PC 端，机器上装在 `D:\eleckoi`）
- [ ] 2. 找到「导入卡」的入口，导入 `向导/制卡助手/成品/制卡助手.card.json`
- [ ] 3. 看**卡名**是不是 `制卡助手`
      —— 不是的话，就是我上一轮修的「卡名被覆盖」还没修干净，告诉我
- [ ] 4. 看**条目**：应该 **14 条**。少一条、多一条、或者全是空的 → 记下来
      （注意：会话里 AI 自报的条目数**不作数** —— 必读 5 条常驻注入，
      关键词条目命中才进来，没触发的它看不见。数条目以卡文件为准）
- [ ] 5. 开一个会话，随便说一句跟制卡相关的话（比如「我要做一张卡」），
      看它会不会照着条目里的规程答
- [ ] 6. 看**变量**：这张卡没带变量，界面上不该冒出莫名其妙的变量格子

**如果第 2 步就卡住（找不到导入入口 / 导入报错）**：截图那个入口，剩下的先别测了，回来找我。

## 乙：带界面层的卡（约 5 分钟，重头戏）

- [ ] 1. 导入 `.workbuddy/盲跑4/盲跑测试卡/成品/盲跑测试卡.card.json`
- [ ] 2. **界面层出没出来** —— 该有的三样：
      - 一个可开合的面板（罗列条目）
      - 开新会话时的**建卡界面**（第一屏）

      少哪样报哪样
- [ ] 3. **开场白显示正常吗** —— 建卡界面第一屏的那段字，是不是完整、有没有

- [ ] 4. 面板里点开一条条目，看正文是不是完整的、有没有被截断
- [ ] 5. 开个新会话，看这张卡能不能正常聊起来（不报错、不白屏）
