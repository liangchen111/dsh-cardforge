## 一、它长什么样

一个**纯宿主插件**，五个文件（比探针还少一个——没有 `client.js`，因为**不画界面**）：

| 文件 | 干嘛的 |
|---|---|
| `package.json` | 包的身份证；`dsh.bundle.patch` 指向下面那份 patch |
| `cordis.patch.yml` | 往 profile 的插件组合里**插一行**，并带上可改的配置（解释器 / 依赖目录 / forge.py 位置 / 默认工作目录 / 超时） |
| `index.js` | 全部逻辑：注册一个 `cardforge` 工具，起子进程跑 forge.py |
| `locale/zh.json` · `locale/en.json` | 插件列表里显示的中英文名与说明 |

`index.js` 的形状是**照官方 `@deepseek-ai/dsh-tool-present` 抄的**（那是官方最小、最干净的
「注册一个工具」范例）——`defineTool` + `ctx.tools.register()`。官方文档原话：

> 注册一个工具就足以让它可见 —— 注册表会自动把其 schema 送入系统提示词组装。

工具的样子：

```
cardforge(args=["new","我的卡","--到","E:/卡库"], cwd="E:/卡库")
   → exitCode: 0 · stdout: 组装完成（卡名：我的卡 …）· stderr: ""
```

- `args`：传给 `forge.py` 的命令行参数，**逐项给**；
- `cwd`：跑命令的工作目录（做卡的落点）；
- 返回 `exitCode / stdout / stderr`，非 0 就是这步没成。

**它还能让 AI 自己把规程取到手**（用法写在工具描述里，AI 不必等人贴）：

```
cardforge(args=["guide"], cwd="E:/卡库")                   → 目录（有哪些节 / 有哪些篇 / 有哪几段「对话」）
cardforge(args=["guide","--篇","写法"], cwd="E:/卡库")       → 「怎么把角色写活」整篇
cardforge(args=["guide","--对话","访谈"], cwd="E:/卡库")     → 「在对话里怎么问玩家」整段
cardforge(args=["guide","--节","六"], cwd="E:/卡库")         → 「验收标准」整节
```

这不是装饰 —— 一份规程一万七千字，一次全塞进上下文既贵又冲淡重点；按需取一段，
AI 的注意力才落在当下这一步上。名字写错（或撞名）会**当场非 0 并列出全部候选**，
所以它不会拿到一段空内容、还以为规程就这么多。

**★ 最省的一条：一次落成。** 内容谈定了，让 AI 把整张卡写成一份**卡稿**，一趟做完：

```
cardforge(args=["make","--示例"], cwd="E:/卡库")     → 打出一张**真能开的完整卡稿**
                                                        （长夜便利店，约 3.8k 字）——照它改
cardforge(args=["make","--模板"], cwd="E:/卡库")     → 或者只要骨架：有哪些键、怎么缩进
cardforge(args=["make","E:/卡库/我的卡.yaml"])        → 建工程 + 写条目 + 加变量正则
                                                        + 换开场白 + 出成品 + 体检，一趟全做完
```

**让 AI 优先走 `--示例` 那条**：`--模板` 只回答「有哪些键」，`--示例` 连
「**话该写多细、哪句放常驻、哪句放关键词**」一起示范。AI 最容易失手的从来不是键名，
是「写多细算够」—— 一份好样板比十条规则管用。（同一份也在
`E:\workGZQ\制卡工具\向导\示例卡稿.yaml`，离线时可以直接读这个文件。）

稿子里的条目按**标题**认人（已有同名的改它、没有才新建），分组与变量对象缺了自动补
（报告里单列一份，名字打错看得见）；给**已有**条目写 `模板:` / `分组:` 也真生效
（换档、挪组都落下去）；稿子有毛病会**一次报全**，而且**一个字都不往目标位置写**。
这比 `new` → `entry` × N → `build` 省掉十几轮对话 —— 在对话里，每一轮都要把前面说过的话
重新过一遍，那是实打实的开销。

## 二、装（三步，约 2 分钟）

### 1. 打开 ElecKoi → 左栏「插件」→「添加插件」

把下面这行**整个**贴进去，点安装：

```
E:\workGZQ\制卡工具\插件\制卡工坊
```

读出来应该显示包名 `@local/cardforge`。装完问「立即启用」→ **点是**。

> 也可以让 ElecKoi 里的 AI 装（它手上有个 `plugin_manager` 工具）：
> 「帮我装一个本地插件，包目录在 `E:\workGZQ\制卡工具\插件\制卡工坊`」。

### 2. ★ 给角色打开「扩展工具」

**这一步最容易漏。** ElecKoi 的工具是**按角色**开开关的，工具来源分三类：
`built_in / mcp / **extension**`。我们注册的工具落在 **`extension`（扩展）** 那一组，
默认**不一定**是开着的。

去**角色的工具设置**里找到「扩展 / extension」那一组，确认它是**启用**状态。
（插件列表里能看到 ≠ 这个角色能用。）

### 3. 回一个会话，问 AI

```
你手上有没有一个叫 cardforge 的工具？有的话跑一下 cardforge(args=["--help"])。
```

## 四、没看到工具时，按这张表查

| 现象 | 意思 | 怎么办 |
|---|---|---|
| 插件列表里根本没有「制卡工坊」 | 没装上 | 看安装时的报错原文；确认贴的是**目录**路径 |
| 列表里有，但开关是灰的 / 显示失败 | 装上了没激活 | 看那一行给的原因（`failed` / `overridden` / `restart-required`）；`restart` 的话重启一下 |
| AI 说没有 cardforge 工具 | 多半是**第 2 步没做** | 去角色工具设置里打开 `extension` 组 |
| AI 调了，报「没给工作目录」 | 它没传 `cwd` | 让它带上 `cwd`；或把默认工作目录写进 `cordis.patch.yml` 的 `cwd` |
| 报「进程没起来」 | 解释器路径不对 | 改 `cordis.patch.yml` 里的 `python` |
| 报 `ModuleNotFoundError: yaml` | 依赖目录不对 | 改 `cordis.patch.yml` 里的 `pythonPath` |

改完 `cordis.patch.yml` **要重装一次**（面板里卸载再装，或走 AI 的 `plugin_manager`）。

## 五、已经验过什么 / 没验过什么

**本机验过（49 项全绿，`\.workbuddy\_插件本地测\` 里可复跑）**
把 `index.js` 原样载入（只把两行官方 import 换成桩件），**真的**用它跑 forge.py：

- 定义层：工具名 / 参数 schema / 描述 / 配置默认值，全对；
- 取规程：`guide` 出目录（节 / 篇 / 对话段三块都在、标出了哪几篇必读）、
  `guide --节 一` 真取到成篇的开工流程（5350 字节）、`guide --对话 访谈` 取到访谈节奏表、
  名字写错时**非 0 并列出全部候选**（不静默给空）；
- **一次落成**：`make --模板` 打出能跑的骨架、`make --示例` 打出**完整的示例卡稿**
  （卡名 / 条目 / 变量 / 正则 / 开场白齐全，且与 `--模板` 那份不是同一个东西 ——
  这条盯着一个老毛病：`--示例` 曾经和 `--模板` 打的是同一份骨架）；
  `make <稿.yml>` 一趟落出一整张卡（报告里说清改/建/删）、成品跟着出来；
  坏稿**当场非 0 且目标位置一个字没写**；
- 真跑：`--help` → `new` → `group --列` → `entry` → `check` → `build` → `check <成品>`，
  **退出码全 0、中文不乱码**；
- **★ 决定性的一条**：`new` 那一步**改名成功**（`source\插件冒烟卡.spec.yaml` 真的叫这个名，
  不是骨架名）—— 这正是**宿主进程不受沙箱管**的证据。成品卡 114 KB 真落盘了。
- 边界：空 `args`、缺 `cwd`、错命令，都被干净地拦下 / 返回非 0 而不是抛异常。

**没验过（只有你的真机能验）**
「装上之后**模型到底看不看得见**这个工具」—— 取决于插件激活与你角色的工具开关。
所以第三节那三句话，前两句请务必跑一遍。

## 六、两条丑话

1. **它默认的路径是写给这台机器的**：解释器、依赖目录、`forge.py` 位置都写死在
   `cordis.patch.yml` 里（也可以在插件面板里改 config）。换机器就改这一处。
2. **它给了 AI 在你机器上跑命令的能力**（跑的还是 forge.py，不是任意命令）。
   这跟「让它用自带命令行工具」权限级别**一样**，但少了沙箱兜底 ——
   只在你自己这台机器上装，别把包发出去。
